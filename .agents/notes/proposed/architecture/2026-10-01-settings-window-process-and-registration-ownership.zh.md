# Agent Note: 设置窗口进程与注册表写入责任（第八期）

Status: proposed

[English](2026-10-01-settings-window-process-and-registration-ownership.md) | 中文

## Problem

仓库目前完全没有设置界面。`zhu-ye-ime` 是一个 TSF `cdylib`，唯一的窗口是候选窗，而
`Cargo.lock` 里没有任何 GUI 工具链——没有 egui、winit、tao、wry、WebView2、Slint，
也没有 Direct2D 绑定。源码树里不存在设置窗口、托盘菜单或属性页。

因此三条已确认的需求无处落地：

- **P-11** 推迟了设置 GUI（`本期不做设置 GUI；领域包启停走配置文件，GUI 设置窗下期交付`），
  自 M6-R 起由配置文件代行界面职责。
- **FR-015** 与 **FR-022** 要求用户在**设置界面**里启用与停用领域包，且 FR-022 固定了该界面
  必须呈现的字段：名称、简介、词条数、体积、版本、启用开关，启用状态需跨重启保持。
- **P-02** 要求设置界面提供手动"检查更新"入口。更新器二进制已存在并已验收，但调用它的
  只有 `zhu-ye-cli dict update`。

这两个缺口背后还压着两个障碍：

- 只要注册责任被固定在安装脚本上，**一键修复**就无法成立。
  [TSF 注册笔记](../../implemented/architecture/2026-09-18-tsf-registration-and-lifetime.md)
  写明注册由 `scripts/install.ps1` 与 `scripts/uninstall.ps1` 管理，`docs/architecture.md`
  复述了同一条不变量（`注册表只由 scripts/install.ps1 / scripts/uninstall.ps1 管理`）。
  已交付的代码没有任何注册表写入，唯一的注册检查实现是 PowerShell 函数
  `Test-TsfRegistration`。
- 打包路径无法交付界面。`install.ps1` 从源码树取 DLL、只复制一个基础词典，既不创建
  `packs` 目录，也不带 manifest、领域包与快捷方式。`package-portable.ps1` 组装的形态相同。

所要求范围本身是明确的：后端尚未落地的条目仍须出现在界面里，标注为规划中，而不是省略。

## Proposal

### 进程形态

新增 `zhu-ye-settings` crate，产出独立进程 `zhu-ye-settings.exe`：原生 Win32 顶层窗口 +
GDI 绘制，复用 `candidate_ui` 已经暴露的纯视图模型与主题逻辑，**不引入任何** GUI 依赖。
输入法 DLL 不新增窗口与界面代码，因此宿主进程内不会有新的东西运行。

首个批次（T-073）取得这份共享逻辑的方式，是给 `zhu-ye-ime` 的 `[lib]` 加 `rlib` 后直接依赖，
而不是在同一次改动里抽出共享原语 crate：抽取必然触碰已交付的候选窗与其测试，等于把一次重构
与一个新建窗口塞进同一个任务。代价是 `zhu-ye-settings.exe` 会连带链接 TSF 侧代码；抽出
`zhu-ye-ui`（颜色、主题种类、矩形、DPI、文本测量，并从 `candidate_ui` 转发以使既有路径继续
有效）即可移除 `rlib`，该工作登记为 T-081。

### 窗口形态与设置分类

单窗口 + 左侧导航三页：工具箱、常用设置、关于与更新。后端尚未落地的条目保持可点击，展开
行内 `正在规划中` 说明；既不灰显，也不用模态弹窗作答。

设置分三类，窗口要呈现这一区分，而不是把一切压平成开关：

- **运行时开关**——立即生效并被持久化。
- **装配项**——写入配置，在输入法下次启动重新装配时生效。
- **会话状态**——立即生效且刻意不持久化。会话中经 Shift 切换的中英模式仍是会话状态，但
  **没有任何设置窗口条目表达它**；窗口的"英文输入法"条目是**装配项**（自 D-32 原稿修订：
  跨宿主进程没有可供窗口展示或切换的单一"当前模式"，唯一有意义的语义是"新输入会话从哪种
  模式开始"，写入 `config.json` 的 `default_mode`，由 TSF DLL 在下次装配（`Activate`）时应用）。

运行时开关在改动时即写入 `config.json`；装配项由显式保存提交。窗口为单实例——再次启动
激活已有窗口——关窗即退出，因此"后台驻留进程数 0"的验收指标保持成立。

### 入口

四条入口，让每一种习惯路径都能到达窗口：

- **`ITfFnConfigure`**，实现在文本服务对象上。Windows 用已经通过
  `ITfInputProcessorProfiles::Register` 注册的同一 CLSID 经 `CoCreateInstance` 取得该接口，
  因此 Windows 设置 → 语言选项里的"属性"按钮即可打开窗口，且**无需新增任何注册表键**。
- **右键菜单项**，加在既有的语言栏按钮上。`InitMenu` 与 `OnMenuSelect` 目前返回 `E_NOTIMPL`；
  只 spawn 进程的菜单项从不接触引擎状态，因此落在
  [语言栏笔记](../../implemented/feature/2026-09-28-language-bar-mode-icon.md) 记录的
  非 `Send` 边界之外。
- **开始菜单快捷方式**，由安装脚本创建。
- **`zhu-ye-cli settings`**，按 `zhu-ye-cli dict update` 转发到更新器的同一方式转发到该可执行文件。

语言栏按钮的**左键单击不会**打开窗口；该手势继续留给语言栏笔记记录为后续工作的模式切换。

### 主题选择

窗口只提供浅色与深色两项。高对比度继续由系统接管，不可手选。候选窗刻意**不提供**"跟随
系统"：固定浅色是已确认的决策
（[浅色默认笔记](../../implemented/feature/2026-09-25-candidate-window-light-default-and-empty-panel.md)），
该笔记本身已把"将来某个用户可见设置"记为通往深色配色的唯一路径。不存在主题文件、用户自定义
配色与在线分发——`不做皮肤商城` 的非目标保持成立。

设置窗口**自身跟随**系统深浅色。这不扰动候选窗的决策，那条决策只约束候选窗。

### 词典包管理与已安装包记录

添加词库页兑现 FR-022 并新增本地 `.zyct` 导入。导入经既有加载路径校验魔数 `ZYDT`、格式版本、
头部布局与内容 SHA-256，且**不验签**——用户自带的包没有发布签名。界面必须写明这一点，因为
导入的包位于
[更新信任链笔记](../../implemented/architecture/2026-09-29-dictionary-update-trust-chain.md)
记录的信任链之外。

FR-022 的字段目前没有单一来源，将按如下方式满足：

| 字段 | 来源 |
| --- | --- |
| 名称、简介 | `zhu-ye-core` 中的静态表 `id → (名称, 简介)` |
| 词条数、体积 | 从 `.zyct` 产物读取——头部 `entry_count` 与文件元数据 |
| 版本 | 新的磁盘记录 `packs/installed.json` |
| 启用开关 | `config.json` 的 `enabled_packs` |

`packs/installed.json` 由在线更新器与本地 `.zyct` 导入共同写入，记录 `id`、`version`、
`sha256`、`source` 与时间。这一分离是刻意的：`config.json` 承载**用户意图**——启用哪些包、
是否允许联网；`installed.json` 承载**机器事实**——磁盘上实际有什么、是什么版本。因此手改
配置不可能悄悄伪造已安装状态。

用户词表导入与导出不在本次范围内。

### 修复：两个权限层级

修复输入法先报告，只有用户按下修复按钮才动手。它从不删除：损坏文件改名为 `.bak` 兄弟文件后
重建，与 `UserDictStore` 既有的恢复约定一致。

- **一级，无需提权。** 检测以 `Test-TsfRegistration` 已编码的三条判据为基础核对 TSF 注册状态
  （语言配置键存在且 `Enable = 1`；`InProcServer32` 存在、其默认值指向 DLL 路径、`ThreadingModel`
  为 `Apartment`），并**另加一条强化：注册指向的 DLL 路径必须实际存在**——安装脚本只与调用方传入
  的路径比对，这正是卸载能用 dummy 路径断言缺席的原因。检测还校验每个 `.zyct` 的头部与内容哈希，
  并确认 `config.json` 与 `user_words.json` 可解析。修复动作是重建缺失的 `packs` 目录、重建损坏
  的配置。
- **二级，需要提权。** 以"先删后建"的幂等方式重注册两棵 HKLM 树。DLL 路径取自当前
  `InProcServer32` 的值，取不到则回退到安装目录下最新的 `zhu-ye-ime*.dll`，因为部署使用
  版本化文件名。当 DLL 本身已丢失时，窗口报告 `输入法文件缺失，请重新安装`，而不假装能修。

提权在按下修复按钮时请求，而不是在窗口打开时。注册修复成功后，窗口提出重启 ctfmon——这是让
注册变更生效的那一步——并在重启前确认，因为重启 ctfmon 会中断所有正在运行的应用的输入。

管理输入法以只读状态展示同一份注册判据，外加一个打开 Windows 输入法设置的按钮。这样"管理
本输入法"与"管理系统里的输入法"保持可区分，且复用了修复路径本来就需要的那份检测代码。

### 检查更新

该页展示状态并提供显式按钮。窗口 **spawn `zhu-ye-updater`** 完成联网，自身从不建立连接，
从而保住"唯一联网组件"这条不变量。`online_update` 保持默认关闭，必须显式勾选；应用更新
需要二次确认。

P-02 的另一半——输入法启动时的异步检查——**不在**本次范围内。它会把进程创建引入输入法的
启动路径，冷启动时延、宿主进程权限与杀软行为都会受影响，而验收 VM 当前不可连，无法验证。
它将立为独立任务。

### 打包

`install.ps1` 将改为从发行物自身取文件而非源码树，安装 `zhu-ye-settings.exe` 与
`zhu-ye-updater.exe`，预置三个领域包，并创建开始菜单快捷方式；`package-portable.ps1` 同步。
三个领域包合计约 2.25 MB，相对 23 MB 的基础包很便宜，预置还能让 FR-022 离线可验收，而不必
每轮验收都付一次网络往返。两个脚本都必须保持
[便携脚本笔记](../../implemented/bug-fix/2026-09-22-portable-scripts-windows-powershell-5-1-encoding.md)
记录的 UTF-8 带 BOM 属性。

### 工具箱内容

工具箱页承载 emoji 面板（复用既有 381 条别名表）与符号面板（复用既有三组各九个符号），按
分类组织，以便将来用更大的符号集填充。符号表扩充是独立任务。图片表情保持占位：TSF 只能插入
文本，图片无法提交进任意宿主；将来最多提供一个复制到剪贴板的动作。

emoji 面板按**字符**去重：别名表中同一个 emoji 有多个别名（`ai`/`aixin` 同为 ❤️），381 条
别名去重后是 342 个不同字符，分入 23 个首字母组。

### 面板投递：第二个非激活窗口

点面板格子必须把字符送进用户真正在打字的那个应用，但用户点击时前台是设置窗口。两条决策让它
成立：

- **面板是独立窗口**，样式 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_TOPMOST`，并对
  `WM_MOUSEACTIVATE` 回 `MA_NOACTIVATE`。因此点它**不会把前台从用户的应用挪走**，
  `SendInput` 配 `KEYEVENTF_UNICODE` 就能把字符投到那里。Windows 自带 emoji 面板即此行为，
  而本项目已有非激活顶层窗口的先例（候选窗）。
- **打开面板时把前台还回去**：在设置窗口 `ShowWindow` 之前用 `GetForegroundWindow` 记下当时
  的前台窗口，打开面板时还给它。焦点只在开关面板时各动一次，不是每次点击都动，因此可以连续
  插入多个字符。

后果：非激活窗口收不到键盘输入，面板没有 Esc 关闭，只能点自己的按钮；前台窗口属于提权进程时
`SendInput` 会被 UIPI 拒绝，此时回退剪贴板并在面板上提示，而不是静默失败。

GDI 无法渲染彩色 emoji：`COLR`/`CBDT` 图层需要 DirectWrite，而设计已连同其他 GUI 框架一并
排除。因此面板字形是单色轮廓，每格另附拼音别名标签以保证条目可辨认；要彩色必须新增
DirectWrite 渲染路径。

## Alternatives considered

**把窗口建在 TSF DLL 内。** 落选：TSF DLL 被加载进任意宿主进程，在其中创建设置窗口与可疑的
宿主行为无法区分，会招来杀软干预。DLL 还会被 ctfmon 在任意 RPC 线程上调用，而引擎状态的
`Rc<Mutex<…>>` 不是 `Send`——正是
[语言栏笔记](../../implemented/feature/2026-09-28-language-bar-mode-icon.md) 已为 `OnClick`
记录的那条边界。

**用 WebView2 渲染。** 落选：它依赖 Edge 运行时而非 Windows 的保证，会给一个刻意轻量的输入法
加上一个浏览器进程，而这个窗口需要的东西 GDI 全都能画。

**引入第三方 Rust GUI（egui/eframe 之类）。** 落选：项目的第一性原理是自研可控、不引入捆绑的
运行时行为。一个导航栏加若干复选框和列表，不值得新增一套 GUI 工具链；候选窗也已经证明了
自研 GDI 这条路可行。

**由语言栏按钮左键单击打开窗口。** 落选：它把最显眼的手势花在价值最低的动作上，并堵死语言栏
笔记记录为后续工作的"点击切换模式"方向。

**继续用 `install.ps1` 充当修复后端。** 落选：它从源码树读 DLL，还可能调用 `cargo`，在用户的
机器上没有检出的源码树就无法运行。它还只装一个基础词典、从不重启 ctfmon，是开发者安装器，
不是修复路径。

**新增 `DllRegisterServer` 并调用 `regsvr32`。** 落选：它会在脚本与设置窗口之外产生第三份注册
实现，让"以哪一份为准"成为新的漂移源，并重新打开
[TSF 注册笔记](../../implemented/architecture/2026-09-18-tsf-registration-and-lifetime.md)
有意关闭的注册路径。

**让整个设置窗口要求管理员权限。** 落选：换主题、启用词库这类日常改动都会弹 UAC，而提权会被
授予得远比真正需要它的那一个操作频繁。

**让设置窗口自己发起网络请求。** 落选：它会打破"唯一联网组件"这条不变量，而正是这条不变量让
"在线功能关闭时零出站连接"可以在一个二进制里被审计。

**为候选窗提供"跟随系统"主题。** 落选：它会反转候选窗已决定的固定浅色。想要深色配色的用户
显式选择深色即可。

**把中英模式持久化为设置。** 在 D-32 原稿中以"该模式是会话状态"为由落选：持久化会制造
"我离开时是中文，回来却变成英文"，也意味着重启会改变下一次按键的结果。**已修订**："英文
输入法"条目现在是**装配项**——持久化的是"新会话的默认模式"（`config.json` 的 `default_mode`），
不是模式本身。窗口无法展示或翻转运行中的模式——它是各宿主进程各自的 IME 实例状态，跨进程
没有单一值——因此原稿"展示当前模式并即时切换"的语义没有东西可展示。会话中的 Shift 切换仍是
会话状态、仍在窗口之外；重启改变下一个会话的*起始*模式，正是装配项的用途。

**用随包发布的 manifest 解析 FR-022 的名称、简介与版本。** 落选：已发布的 manifest 是远端发布
产物，从不写入本地 packs 目录，因此从它读取需要凭空造出第二份本地 manifest——正是
`installed.json` 通过只承载更新相关事实而避免的那份重复。

**把 `.zyct` 头部扩展到格式 v3 以承载名称、简介与版本。** 落选：128 字节头部里只有 20 字节
未被写入（偏移 76..80 与 112..128），装不下中文名称与简介，所以这是改格式而不是加字段——
为一份属于分发、不属于词典内容的元数据付出过大代价。

**把已安装包记录存进 `config.json`。** 落选：它把机器事实混进用户会被期望手改的文件，而"我改了
配置，状态就没了"正是这样发生的；配置加载器已经把损坏视为回退默认的理由。

**加入用户词表导入与导出。** 本次落选：它需要先设计一种新的文本格式契约（字段分隔、拼音标注、
多音字处理），而这份契约本身就是一个独立项目。

**占位条目灰显，或用模态弹窗作答。** 落选：灰显把条目将来会做什么藏了起来，模态则要为每个占位
打断用户一次。行内说明既保留条目的可发现性，又能解释它。

**把符号表扩充并入本次。** 落选：符号语料是数据工作，有自己的来源、许可与审核链条。拆开之后，
面板可以先交付并验收，不必等语料。

**在本次实现 P-02 的启动时检查。** 落选：它把进程创建放进输入法启动路径，而验收 VM 不可连，
最关键的行为——真实宿主加载 DLL——无法被观察到。

## Acceptance criteria

- 在已注册输入法的机器上，窗口能从四条入口打开：Windows 设置里的"属性"按钮、语言栏右键菜单、
  开始菜单快捷方式，以及 `zhu-ye-cli settings`。
- 每页只列出约定的条目。占位条目（图片表情、简繁切换、全半角切换、生僻字输入）显示行内
  `正在规划中` 说明，不触发其他动作。
- 选择深色后，输入法重启后候选窗配色随之改变，且该选择跨重启保持；高对比度仍由系统接管。
- 在窗口中启用某个领域包、保存并重启后，实际加载的包随之改变，且启用状态跨重启保持。
- 每个包行都显示名称、简介、词条数、体积与版本；名称与简介来自内置表，计数来自产物，版本来自
  `packs/installed.json`。
- 导入一个合法的本地 `.zyct` 后，它以自身的词条数与体积出现，并显式声明它未签名、位于更新信任链
  之外；导入魔数错误、格式版本不受支持或内容哈希损坏的文件时被拒绝并显示原因。
- 经窗口写入的配置是原子的；用刻意损坏的 `config.json` 启动时回退默认并报告问题。
- 一级修复面对刻意损坏的用户词库时先声明损坏，并在显式按下后重建，留下 `.bak` 兄弟文件且无词条
  丢失。
- 二级修复在提权状态下、针对手工删除的注册表键，恢复两棵 HKLM 树，且提出的 ctfmon 重启能让
  正在运行的应用恢复输入。DLL 被移除时，窗口报告需要重新安装，而不声称修复成功。
- `online_update` 关闭时按下"检查更新"产生零出站连接；打开时窗口报告更新器的结果，并在应用前
  请求二次确认。
- 在干净机器上 `install.ps1` 安装两个可执行文件、三个领域包与开始菜单快捷方式；`uninstall.ps1`
  不留注册表残留，也不留 packs 目录。
- `Cargo.lock` 不新增 GUI 依赖，且 `zhu-ye-ime.dll` 的导出不超过今天已有的那些。
- 宿主侧证据齐备：设置三分行为、注册判据检测、修复决策与包元数据组装的单元测试，以及三页的
  BMP 截图。
- VM 上的交互验收——入口、真实注册表写入、ctfmon 重载——写成条目，并在 **VM 恢复后回填**。
  在此之前，本期报告"实现完成、验收欠账"，且其中任何任务都不标记为已完成。

## Risks

**注册责任扩散到两份实现。** 标识常量目前存在于 `crates/zhu-ye-ime/src/tsf.rs` 与
`scripts/ime-identity.ps1`，仅靠注释保持一致。Rust 侧再出现第二个写入者会加倍漂移概率。缓解：
新增交叉一致性测试，把 Rust 常量与 `ime-identity.ps1` 导出的值对比，并纳入推送前门禁；没有它，
本提案不应落地。

**第二个写入者让"部分修复"成为可能。** 二级修复写两棵 HKLM 树，中途失败会留下半应用的注册。
缓解：修复必须保持幂等且可复检，修复后的判据来自只读状态用的同一条检测路径，因此半成品会被
报告为失败而不是成功。

**`installed.json` 是有两个写入者的新持久格式。** 更新器与本地导入路径必须对它的 schema 达成
一致，文件需要版本字段，以及"版本过高怎么办"的规则。删除或损坏它必须退化为"不显示版本"，绝不
退化到启动失败。

**对应用数据目录的并发写入。** 设置窗口、更新器与输入法读取路径都触碰 `%APPDATA%\zhu-ye-ime`。
两个进程同时写 `config.json` 会互相覆盖——最具体的是窗口保存会丢掉更新器的 `last_check`。
原子写本身关不上这个窗口；设计所采用的任何重读或单写者规则，两个写入方都必须遵守。

**一个写 HKLM 的修复按钮是界面里的权限边界。** 此处缺陷可能破坏其他文本服务的注册。缓解：写入
集合被限定在安装器本来就拥有的两棵树上，操作与安装器一样是先删后建，且只在显式按下时执行。

**打包改动会让既有安装验收失效。** 安装与卸载是通过当前不可用的 VM 演练验收的，因此安装器的
回归可能一直不被察觉，直到 VM 恢复。

**VM 不可连留下验收欠账。** VM 不可连期间本期无法结项，与今天 T-061、T-062、T-067 的处境相同。
欠账必须被记录，而不是被掩盖。

**`ITfFnConfigure::Show` 在不由我们选择的线程上运行。** 它必须遵守与 `OnClick` 相同的规则：
除 spawn 设置进程外不做任何工作，且绝不接触引擎状态。

**占位是面向用户的承诺。** 四个条目以 `正在规划中` 交付，每一个都对应一个真实项目（图片表情、
简繁转换、全半角转换、生僻字输入）。长期搁置会侵蚀用户对这个窗口的信任。

**设置窗口跟随系统主题而候选窗不跟随。** 这是刻意的，仍可能成为"这看起来像缺陷"的报告来源。

**本次有意放弃的东西：** 提交进宿主的图片表情、符号表扩充、用户词表导入与导出、主题文件与
用户自定义配色、启动时更新检查、托盘常驻，以及语言栏点击切换手势。此外，这个窗口还意味着新增
一块需要长期维护的 GUI 表面，带有自己的 DPI、布局与无障碍问题。
