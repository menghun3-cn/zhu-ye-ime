# Agent Note: Host-side end-to-end regression

Status: implemented

[English](2026-09-21-host-e2e-regression.md) | 中文

## 问题

FR-001 至 FR-007 的核心输入行为此前有单元测试和零散的 CLI 检查，但没有一条可重复执行的主机侧命令能在虚拟机验收前验证词典驱动的输入闭环。虚拟机环境尚未就绪时，改动之间的回归可能被漏掉。

## 决策

`crates/zhu-ye-ime` 现在提供 `host-e2e` 检查器：加载 v2 词典文件并驱动 `InputEngine`，执行 17 项种子检查：词典加载、`nihao` 候选与行内译文、`xian` 歧义、排序确定性、数字选择、候选翻页与回卷、空格/回车/Esc、Shift 模式、用户词提升与持久化、删除/重置、bigram 上下文排序、译文层切换、无译文兜底、正向与反向翻译。`scripts/e2e.ps1` 会确保 `data/artifacts/seed.zyct` 存在，构建检查器并执行；当 `data/artifacts/real.zyct` 存在时，再执行真实词典 smoke（`jiao` 保留叫、`xian` 无洗按、你好/good 翻译可解析）。任一检查失败都会让检查器以非零退出码结束，因此脚本可以作为门禁使用。

## 曾考虑的替代方案

**只扩展现有 cargo 单元测试。** 否决：单元测试不是验收命令。PowerShell 脚本把可执行检查器变成可重复、可机器识别的门禁，同时保留按项可读的输出。

**解析 `demo`/`rank` CLI 文本。** 否决：文本快照脆弱，且 `demo` 不覆盖提交流程、用户词提升与译文层。

**等待虚拟机验收。** 否决：主机侧现在就能覆盖完整核心算法；虚拟机验收仍然聚焦 TSF 注册、候选窗渲染与系统级交互。

## 影响

词典与输入相关的每次改动都可在开发机上通过 `scripts/e2e.ps1` 做门禁。种子词典保证检查确定性；真实数据 smoke 是可选项，只在产物存在时执行。该检查不替代虚拟机上的 TSF 与 GUI 端到端验收。
