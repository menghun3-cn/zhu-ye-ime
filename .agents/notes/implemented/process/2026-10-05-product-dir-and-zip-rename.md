# Agent Note: Product path / package naming de-`ai-` renaming (T-108, T-109)

Status: implemented

English | [中文](2026-10-05-product-dir-and-zip-rename.zh.md)

## Problem

The released artifact and the product directory paths carried an `ai-` prefix
(`ai-zhu-ye-ime-<v>.zip`, `%APPDATA%\ai-zhu-ye-ime`,
`Program Files\ai-zhu-ye-ime`, `%LOCALAPPDATA%\ai-zhu-ye-ime\logs`, TSF install
dir `ai-zhu-ye-ime\tsf`). The user asked to drop the `ai-` prefix for the zip
name first and then for the product directories, and explicitly requested **no
backward compatibility**: the old names are not kept and no migration is done.

## Decision

### Renamed to `zhu-ye-ime` (user-direct instruction, no compat)

- Published zip: `zhu-ye-ime-<v>.zip` (v0.1.2 old-name asset deleted from the
  release — asset id 612718330; same-day re-published new-name zip
  19,699,745 B).
- Package top-level dir: `zhu-ye-ime-<v>-test/` (from
  `package-portable.ps1` `$packageName`); staging dir and dev test-zip names
  follow.
- Product directories: `%APPDATA%\zhu-ye-ime` (config / packs / themes /
  user_words.json / update_status.json), `Program Files\zhu-ye-ime` (install
  root, `\bin`, TSF `\tsf` via `TSF_INSTALL_DIR_RELATIVE`),
  `%LOCALAPPDATA%\zhu-ye-ime\logs` (product log), HKCU per-user TSF DLL
  location `%LOCALAPPDATA%\zhu-ye-ime\tsf`.
- **Unchanged**: exe name `ai-zhu-ye-ime-setup-<v>.exe` (not in scope of either
  instruction), product/project name 竹叶输入法（ai-zhu-ye-ime）(README title,
  Cargo authors), historical records (todos-done, released CHANGELOG sections,
  acceptance evidence rows), `C:\zhu-ye-test` sentinel path.

### No migration / no legacy handling

- install.ps1 does not copy from `%APPDATA%\ai-zhu-ye-ime`; uninstall.ps1 only
  cleans the new dirs; no dual-path reads anywhere. Upgrading from a v0.1.2
  install requires reinstall (old dirs are simply not used).
- v0.1.2 release holds only the new-name zip; SHA256SUMS.txt re-generated by
  staging with the new name row (no old-name row).

## Consequences

- `verify-tsf-identity.ps1` gate keeps both sides consistent: Rust
  `TSF_INSTALL_DIR_RELATIVE = "zhu-ye-ime\\tsf"` ↔ `ime-identity.ps1`
  `Get-TsfInstallDir` `'zhu-ye-ime\tsf'`.
- Path unit tests updated with the new literals (settings `product_log_dir`,
  tsf `product_log_path`, base-dir fixture `C:\Program Files\zhu-ye-ime\tsf`).
- The zip content changes (top-level dir name), so the release asset must be
  rebuilt via `workflow_dispatch` (upload=true) after this lands.
- Docs/site/active Agent Notes updated in place; released CHANGELOG sections
  and archived/historical records keep the old names as the then-current fact.

## Alternatives considered

- **Keeping the old-name asset alongside** (compat) — rejected by explicit
  user instruction; deleting it keeps the release and SHA256SUMS self-consistent.
- **Shim/redirect at install time (migrate old data dir)** — rejected: user
  asked for no backward compatibility; migration code would persist two path
  families in the codebase forever.
- **Renaming the exe too** — not in scope; both instructions named the zip /
  directories explicitly, so the exe name was left untouched to avoid an
  unrequested breaking change.
