# Agent Note: 工具箱面板给应用级窗口让位，定时器与类名比较的三个陷阱

Status: implemented

[中文](2026-10-21-panel-yields-to-app-window.zh.md) | English

## Problem

用户报告：竹叶输入法的托盘图标右键菜单里，「模式」「工具箱」「打开设置」「退出」**四个菜单项都弹出「emoji… 符号大全」窗口**。

取证过程（先排除误判）：

1. 用户提供的截图里，窗口标题是「emoji… 符号大全」，内含「点击输入关键词过滤（拼音别名/字符）」「点击格子上屏 · 呼出热键 Ctrl+Alt+E」「1/6 上一页 下一页」等文案 —— 这些是**本项目自己的**界面文案（`zhu-ye-settings/src/panel_window.rs`）。
2. 「符号大全」这一字串**同时**存在于 `C:\WINDOWS\System32\SogouPY.ime`（搜狗拼音的 `IDB_MENU_SUPER_SYMBOL` 菜单项）。**只按字串搜索会误判归属** —— 本次缺陷与搜狗无关。

面板窗口类为 `ZhuYeSettingsPanel`，尺寸 875×724，位置记忆文件 `%APPDATA%\zhu-ye-ime\panel.json` 记录为 `{"kind":"Emoji","left":522,"top":148,"width":875,"height":724}` —— 与截图一致。

## Decision

### 面板是瞬态浮层，遇到应用级窗口必须让位

面板按设计（S-11）是 `WS_EX_NOACTIVATE │ WS_EX_TOOLWINDOW │ WS_EX_TOPMOST` 的**非激活浮层**，目的是浮在用户正在打字的宿主应用之上，且不抢焦点。

但设置窗口是**应用级窗口**，比浮层「更重」。面板压在它上面时，用户点「打开设置」看到的是面板，**会以为设置没打开**。

修法：面板可见期间周期检查「是否有可见的设置窗口与面板矩形重叠」，重叠则临时降为 `HWND_NOTOPMOST`（让位），设置窗口消失后恢复 `HWND_TOPMOST`。面板**不夺取焦点**这一点不变（`WS_EX_NOACTIVATE` 保留），因此宿主应用仍在前台。

### 第二道防线：托盘打开设置前先关面板

面板可能由**设置窗口自己**创建（跨进程），此时托盘的进程内状态看不到它。托盘在 `open_settings()` 里按窗口类名 `FindWindowW` 找到面板并发 `WM_CLOSE`（面板自己的 `WM_CLOSE` 走 `DestroyWindow` 并写回位置记忆）。

两道防线互补：防线①管「面板已开着时设置窗口出现」，防线②管「用户点打开设置时把浮层收掉」。

### 三个必须记录的陷阱

本次修复连带暴露了三个**同一类**的隐蔽错误，均为「能编译、能测试、真机却不工作」：

**① `SetTimer` 的 ID 语义。** `SetTimer(hwnd, nIDEvent, …)` 在 `hwnd` 非空时**由系统自行分配 ID**，其返回值才是新定时器的 ID；`WM_TIMER` 的 `wParam` 携带的是这个返回值，**不是**传入的 `nIDEvent`。原代码用常量比较 `wparam.0 == ESCAPE_WINDOW_TIMER`，因此**两个定时器从未触发** —— 包括 T-169 的「浏览态 Esc 关闭窗口期」（潜伏约半年）。修法：把 `SetTimer` 的返回值存入 `PanelState`（`yield_timer_id` / `escape_timer_id`），比较时用它。

**② `to_utf16` 的尾部 NUL。** `crate::wide::to_utf16` 产出**带尾部 NUL** 的序列（`"ZhuYeSettingsWindow"` 长度 17），而 `GetClassNameW` 返回的 `len` **不含** NUL（长度 16）。直接比长度会**永远不相等**，判据恒为假。同一陷阱此前已在 `launch_settings` 修过一次，换函数又踩一次。修法：抽出纯函数 `class_name_matches`，按「前 `len` 个单元」比较，并补单测锁死。

**③ 层级映射的取反关系。** 目标层级 `should_yield ⇒ NOTOPMOST`，当前层级 `is_topmost ⇒ TOPMOST` —— 两者是**相反**的映射，故「目标 == 当前」的条件是 `should_yield != is_topmost`。写反会让面板永远压住设置窗口。修法：抽出纯函数 `target_topmost` 并补单测。

此外还有一处：托盘的 `pump_panel_messages` 用 `PeekMessageW(hwnd = Some(panel))` 取消息，只取**投递到该窗口**的消息；而 `WM_TIMER` 由系统投递到**线程消息队列**、不绑定窗口 ⇒ 被过滤掉。改为 `hwnd = None`（取线程队列全部消息）并只处理属于面板或线程级的消息。

> **后续修正（2026-10-21）**：本笔记的「第二道防线」（托盘 open_settings() 先关面板）**从未生效** —— FindWindowW 的类名参数没有 NUL 终止，根本找不到面板。已由 2026-10-21-wide-string-nul-termination 修复（新增 WideString 类型，4 处参数改为带终止符）。本笔记的「让位机制」部分仍然有效。

## Alternatives considered

**让面板在任何应用级窗口出现时自动关闭。** 否决：面板是用户主动呼出的浮层，用户可能正想在设置窗口旁边查符号；自动关闭会打断操作。让位（降层级）比关闭更贴合「瞬态浮层」的定位。

**给面板加 `WS_EX_TRANSPARENT` 或让设置窗口强制置顶。** 否决：`WS_EX_TRANSPARENT` 影响绘制性能与命中测试；让设置窗口置顶会与「面板浮在宿主应用之上」的设计冲突（面板就该盖在普通应用之上）。

**把让位逻辑放在设置窗口侧（打开时通知面板降级）。** 否决：跨进程通知需要引入 IPC 机制；而面板自己周期检查「有没有应用级窗口」是零通信成本的做法，且设置窗口与面板同在用户桌面时必然可见。

**只做第二道防线（托盘打开设置前关面板）。** 否决：设置窗口也可能是被别的路径打开的（例如系统输入法设置里的「选项」经 `ITfFnConfigure::Show`），此时面板仍会压住它。两条路径都要覆盖。

## Consequences

- 真机症状消除：面板开着时打开设置窗口，面板在 500ms 内降为普通顶层窗口、设置窗口可见；关闭设置窗口后面板恢复置顶。两条行为均有程序化验证。
- 顺带修好 T-169 的 Esc 关闭窗口期（`WM_HOTKEY` 呼出面板后 1500ms 内可按 Esc 关闭）—— 它与让位定时器踩的是同一个 `SetTimer` 陷阱。
- 新增单测 3 个：`类名比较容忍尾部空字符`、`矩形重叠判定`、`让位时目标不是置顶`。三处易错点由此不再靠记忆。
- 面板让位判定为**矩形相交**（边界相接不算），与用户「设置窗口被盖住」的直观感受一致。
- 「符号大全」与搜狗拼音的同名菜单项无因果关系；本次未对第三方输入法做任何对抗性处理。
