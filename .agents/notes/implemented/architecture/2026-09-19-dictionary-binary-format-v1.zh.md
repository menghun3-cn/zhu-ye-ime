# Agent Note: Dictionary binary format v1 and mmap loading

Status: implemented

[English](2026-09-19-dictionary-binary-format-v1.md) | 中文

## 问题

输入法需要一条词典数据管线，能从很小的演示种子扩展到真实词表，而不必在各个 crate 里散落临时加载器。桌面输入法不能接受把大型词典整体读入堆内存；无版本的二进制格式也会让升级与损坏检测变得含糊。T-007 需要经过校验的音节表，T-008 需要真实的 bigram 统计；两类消费方都应走同一条规范化数据路径。

## 决策

版本化 v1 二进制词典格式只在 `zhu-ye-core::dict_format` 中定义一次，由构建器、加载器与 CLI 共用。文件开头为四个字节 `ZYDT`、版本 `1` 与固定 96 字节头部；内容 SHA-256 存放在头部第 56..88 字节，覆盖头部之后的全部字节。布局为：

```text
Header        96 字节：魔数、版本、数量与偏移、SHA-256
Pinyin index  24 字节/条：拼音文本偏移/长度、词条起始/数量、命中总数
Entry table   24 字节/条：拼音索引、词频、译文偏移/长度
Bigram table  16 字节/条：前词/后词条目索引、共现频次
Text pool     UTF-8 变长文本；偏移从 1 开始，0 表示无译文
```

`dict_builder::build_v1` 生成确定性字节：词条按拼音分组排序，文本池去重，bigram 合并，所有数量与偏移都来自同一份源数据。`zhu-ye-core::dict_loader` 中的 `DictionaryFile` 以 mmap 只读打开文件，加载时校验魔数、版本、长度、哈希、UTF-8、分区与排序不变量，并基于记录视图同时实现 `Dictionary` 与 `BigramModel`，不把文件复制进堆内存。

`zhu-ye-dict` 负责 CLI：`build` 默认写入 `data/artifacts/seed.zyct`，`inspect` 输出头部统计，`verify` 完整加载一次并检查每个可见词条与 bigram。`zhu-ye-cli demo` 与 TSF 适配层优先尝试应用数据目录或产物文件，文件缺失或损坏时回退到内存演示词典。

## 曾考虑的替代方案

**JSON 或文本词表。** 否决：易于调试，但加载时需要完整解析、占用更大磁盘空间，也无法安全支持 mmap 条目查询。

**SQLite。** 否决：会引入沉重的第三方依赖与运行时复杂度，项目有意避免；词典是只读派生产物，不是在线事务数据库。

**整文件压缩。** v1 否决：压缩包无法直接 mmap 访问，更适合以后作为独立的发布传输格式；v1 保留原始记录，让加载器保持最小。

**用 CC-CEDICT 或其他第三方来源做种子。** 否决：许可证立场仍在审查，因此 v1 内置自建演示种子，第三方数据登记在 `docs/licenses.md` 单独处理。

## 影响

词典管线现在只有一份字节契约和一条经过验证的加载路径：构建文件、计算哈希、mmap 加载、查询。测试覆盖字节流往返、确定性构建、内容篡改拒绝、稳定排序，以及输入引擎中文件驱动的候选生成。引入真实音节与 bigram 数据后，T-007 与 T-008 可直接复用同一个加载器。

mmap 保持内存平稳，操作系统只按查询命中的记录分页。未来格式变更必须提升 `DICT_VERSION`，并保持头部与哈希契约稳定；在格式仍是内部格式期间，迁移策略刻意不在范围内。
