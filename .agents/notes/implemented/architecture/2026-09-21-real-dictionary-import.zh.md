# Agent Note: Real dictionary import pipeline from CC-CEDICT and word frequency data

Status: implemented

[English](2026-09-21-real-dictionary-import.md) | 中文

## 问题

T-006 定义了词典数据管线，但当时可用词典数据只有 20 词条的自建演示种子。FR-002 需要真实 unigram 词频支撑候选排序，FR-007 需要带拼音的真实双语词条，输入引擎才能提供译文候选。原始数据必须通过可复现的导入阶段进入管线，而不能手工复制进源码，因为派生词典必须保持确定性、许可证合规且可随时重建。

## 决策

`zhu-ye-dict import` 读取 CC-CEDICT 与 FrequencyWords 中文词频，并可选地读取 OPUS GlobalVoices 中文分词语料统计 bigram，最终编译真实 v2 词典。解析器通过定位 `[拼音]` 定界符识别官方空格分隔的 `简体词 [pin1 yin1] /译文/` 格式，也兼容旧制表符分隔形式，不依赖字段数量。每条数据在编译前依次通过五条清洗规则：

1. 简体词必须是纯 CJK 词形。
2. 拼音按空格/撇号拆成音节，归一化为无调 ASCII（`ü`/`u:` 转 `v`），并逐音节校验引擎同款 410 音节标准表。
3. 音节数必须等于汉字数。
4. 同词且同无调拼音只保留首条。
5. FrequencyWords 计数映射到对应词；未命中词频的词计为 1。

多音节拼音不会在校验前直接连成一个串，否则会丢失音节边界；连拼只在校验通过后进行，因此词典键仍与引擎查询（如 `nihao`）保持一致。

2026-09-21 的真实导入从 125,113 行 CC-CEDICT 中接收 120,028 词条，命中 28,130 条词频，参与校验 318,015 个音节，丢弃 894 个非标准音节；同一批构建消费 OPUS GlobalVoices v2018q4（`mono/zhs.tok.gz`）的 397,039 行语料，产出 820,368 个唯一 bigram 词对。bigram 清洗把每条语料行视为独立上下文，只保留纯 CJK 的空白分词，并按词典最长匹配拆词（最多 8 字）；未命中的字符断开上下文，避免标点与未知片段产生跨句共现。计数饱和到 v2 格式的 `u32` 上限。数据源 URL、许可证、SHA-256、清洗规则、复现命令与结果哈希记录在 `docs/数据清单.md` 与 `docs/licenses.md`；原始文件与生成产物不进入 git。导入词典现在已携带真实 bigram 记录，T-008 的候选排序验证可直接针对 `data/artifacts/real.zyct` 进行。

## 曾考虑的替代方案

**按字段数拆分拼音区段。** 否决：官方 CC-CEDICT 导出使用空格分隔，且 `[...]` 内的拼音本身也包含空格，仅凭分隔符数量无法稳定识别简体词、拼音与译文。按括号定位对当前空格分隔与旧制表符分隔都有效。

**直接使用第三方预编译词典二进制。** 否决：项目原则是数据管线自研可控、确定性，并兼容自定义 v2 mmap 格式。从开放文本导入能让许可证与构建路径都可审计。

**同词且归一化拼音相同仍保留多条。** 否决：无调拼音键无法区分归一化后相同的读音，保留多条只会在拼音索引里留下最后一条，使构建输入不一致。按“词 + 无调拼音”保留一条可保证 `build_v2` 确定性。

**不对空白分词做词典切分直接计数。** 否决：OPUS 中文 token 常常横跨多个词典词或夹带标点，原始 token 相邻会引入噪声与罕见词对。只对导入词表切分，能让 bigram 统计与同一词典内的词条保持一致。

**引入外部分词引擎（例如 jieba）。** 否决：会带来大型依赖和一套切分约定不同的第二词表。词典最长匹配确定性高、许可证负担低，且足以支撑静态共现统计；更细的分词属于用户侧 AI 功能，不应进入离线导入路径。

## 影响

管线现在能产出 120,028 条真实双语词条、unigram 词频与 820,368 个真实 bigram 记录，未知音节样本列表仍然为扩充引擎音节表提供了具体信号。生成产物不入库，因此正式发布打包前，运行时仍默认使用种子词典。CC-CEDICT 与 FrequencyWords 内容为 CC BY-SA 4.0，GlobalVoices 内容为 CC BY 3.0；未来分发任何派生词典包时，必须对适用来源署名并遵守相同方式共享要求，原始数据与本地产物不属于仓库内容。
