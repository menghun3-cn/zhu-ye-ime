# Agent Note: 托盘菜单命令必须用 TPM_RETURNCMD 取回，符号大全面板暂禁

Status: implemented

[中文](2026-10-21-tray-menu-command-dispatch.zh.md) | English

## Problem

用户报告：竹叶输入法托盘右键菜单里，「模式」「工具箱」「打开设置」「退出」**四个菜单项点哪个都弹出「emoji… 符号大全」**。用户明确指出「**最早的时候都没有这个问题，怎么改出来的**」。

### 症状的真相

「符号大全」是本项目的工具箱面板（窗口类 `ZhuYeSettingsPanel`）。前面两轮（`2026-10-21-panel-yields-to-app-window`、`2026-10-21-wide-string-nul-termination`）都把它当成「面板压住设置窗口」或「类名参数缺 NUL 终止」来修，**都只修到了旁支**：让位机制与 `WideString` 确实各自修好了独立缺陷，但**用户报告的现象根本没被触及**。

真机复盘暴露的关键事实是：**「退出」菜单项也是坏的** —— 点它之后托盘图标消失、进程却常驻。这与「符号大全」是**两个不同的症状**，却来自**同一处**。

## Decision

### 根因：T-169 把菜单命令的取回方式改错了

Windows SDK 头文件（`WinUser.h`）的权威签名：

```c
WINUSERAPI
BOOL
WINAPI
TrackPopupMenu(HMENU, UINT, int, int, int, HWND, const RECT *);
```

**返回类型是 `BOOL`**，不可能是菜单命令 ID。同一头文件里：

```c
#define TPM_NONOTIFY  0x0080L   /* Don't send any notification msgs */
#define TPM_RETURNCMD 0x0100L
```

`TPM_NONOTIFY` 的注释反证：**默认（不带 `TPM_RETURNCMD`）会发送通知消息**，即 `WM_COMMAND`。

git 历史给出完整对照：

| | T-169 之前（`ce823df`） | T-169 之后（`b031c76`） |
| --- | --- | --- |
| 菜单命令来源 | `WM_COMMAND` 消息 | `TrackPopupMenu` 返回值 |
| `WM_COMMAND` 分支 | ✅ 存在 | ❌ **被删除** |
| `TPM_RETURNCMD` | 不需要（走消息） | ❌ **没有加** |
| 结果 | 点「打开设置」正常 | `picked` 只能是 0/1 |

`picked` 恒为 `0`（取消）或 `1`（成功），而 `MENU_OPEN_PANEL == 1` ⇒ **点任何菜单项都被判成「工具箱」** ⇒ 弹出符号大全面板。`MENU_OPEN_SETTINGS`（2）与 `MENU_EXIT`（3）永远不成立 —— 这解释了「退出」也是坏的。

**用户「最早的时候都没有」的直觉完全正确：这是 T-169 引入的回归。**

修法：`TrackPopupMenu` 加 `TPM_RETURNCMD`，返回值即命令 ID；`WM_COMMAND` 分支不必恢复（模态菜单期间窗口过程收不到普通消息，且面板需要自己的消息循环）。

### 符号大全面板暂禁（用户指令）

用户要求「先把符号大全功能禁用，先保留原来竹叶输入法的设置功能」。实现为**单一开关** `PANEL_ENABLED: bool = false`，统一控制托盘侧的全部面板入口：

- 菜单「工具箱(&T)…」项；
- 全局热键 `Ctrl+Alt+E` 的注册；
- `WM_HOTKEY` 的处理。

恢复时改一处常量并同步放回菜单项与热键注册即可，不必翻代码找散落的位置。

设置窗口内的工具箱条目**未禁用** —— 它是设置窗口自己的功能项，与「点托盘菜单弹符号大全」无关，保留以维持设置功能完整。

### 「退出」需延后到菜单收起后执行

`request_exit` 原本调 `PostQuitMessage(0)`。但 `show_menu` 是在 `TrackPopupMenu` 的**模态循环**内执行的 —— 模态循环自己的 `GetMessage` 会取走 `WM_QUIT` 并直接结束循环，该消息就此消失，主消息循环再也等不到它，托盘退不出去（真机症状：点「退出」后图标消失但进程常驻；实测点过后 `ZhuYeTrayHostWindow` 仍存在且进程 PID 不变）。

改法：`request_exit` 改为投递自定义消息 `WM_APP_EXIT`，由主消息循环在菜单完全收起后处理并 `PostQuitMessage(0)`。

> **后续修正（2026-10-21）**：本笔记修的是「菜单命令**怎么取回**」；另有一处「菜单**拿不到输入焦点**」的独立缺陷（点外部不关闭菜单、点菜单项也点不动），根因是拥有者窗口不在前台，见 2026-10-21-tray-menu-outside-click-dismiss。

## Alternatives considered

**恢复 `WM_COMMAND` 分支而不是加 `TPM_RETURNCMD`。** 否决：`WM_COMMAND` 会在模态菜单期间送达窗口过程，而面板窗口需要自己的消息循环（T-169 的 S-35 约束）。`TPM_RETURNCMD` 把命令**同步带回**调用点，语义更干净，也不依赖窗口过程是否在处理消息。

**只加 `TPM_RETURNCMD`，不动「退出」。** 否决：实测「退出」也是坏的，属同一根因的另一面。`WM_QUIT` 被模态循环吃掉是独立缺陷，必须一并修。

**直接删除面板相关代码（而非开关）。** 否决：用户要求「先禁用」而非「移除」，且面板代码与设置窗口共享。开关可回滚，且恢复成本是一处常量。

**保留「工具箱」菜单项但让它无反应。** 否决：留一个点了没反应的菜单项比不显示更糟。

## Consequences

- 用户报告的四个菜单项症状消除。真机验收（2026-10-21，用户本人操作）：点「打开设置」正常弹出设置窗口、点「退出」托盘正常退出，**「符号大全」不再出现**。
- 符号大全面板在托盘侧不可用（菜单项与热键均已移除）。设置窗口内的工具箱条目仍可用。
- 新增回归测试 2 个：`菜单命令用返回命令取回`（断言 `TrackPopupMenu` 带 `TPM_RETURNCMD`，且菜单项 ID 不得等于 `1` —— 不能与「成功」的返回值混淆）、`符号大全禁用时托盘无面板入口`（断言面板入口受 `PANEL_ENABLED` 保护）。另有既有测试 `菜单动作在模态菜单收起后执行` 随菜单项调整更新。
- 前两轮笔记记录的「让位机制」与「`WideString`」两处修复**依然有效**，但它们修的是**旁支缺陷**，不是本轮用户报告的根因。三者互不替代。
- **教训**：前两轮之所以连续偏离，是因为**只验了程序化路径、没有验用户实际点的那条**。UI 自动化在 Win11 通知区浮出层上不稳定，最终靠用户本人真机点击才闭环。**验收必须对齐用户的真实操作序列。**
