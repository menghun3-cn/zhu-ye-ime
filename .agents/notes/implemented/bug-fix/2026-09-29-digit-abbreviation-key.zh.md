# Agent Note: 含数字缩写键的数字键可达性

Status: implemented

[English](2026-09-29-digit-abbreviation-key.md) | 中文

## 问题

网络语包（T-045）入库了一批含 ASCII 数字的缩写键——`u1s1`、`996`、`520`、
`1314`、`886`、`88`、`233`、`666`、`555`、`7456`。包内键本身完全正确：直接查询
`slang.zyct` 能取回全部十个键及其词与词频。但它们从键盘上无法输入。

两个互不相干的原因，都在按键路径上：

1. `InputEngine::handle_letter` 只接受 `c.is_ascii_lowercase()`，TSF 适配层送来的
   数字被直接丢弃，进不了组合串。
2. `classify_key` 把 `VK_1..VK_9` 直接绑定为 `KeyAction::Select`，因为数字 1-9
   用于选择候选（FR-006，T-040 已验收）。数字键因此从未有机会表示"缩写键的一部分"。

VM 验收（T-048）证实了这一分界：纯字母缩写键可用（`yyds` → 永远的神、
`xswl` → 笑死我了、`zqsg` → 真情实感、`dbq` → 对不起、`yysy` → 有一说一、
`awsl` → 啊我死了、`gkd` → 搞快点），而十个含数字键全部不产生任何候选。

设计约束在于两种含义无法按单次按键区分：用户按下 `996` 的第一个 `9` 时，输入法
无从判断这是字面数字、第 9 个候选选择，还是 `996` 的开头。

## 决策

数字键同时保留两种含义，靠词典查询消歧。

`InputEngine` 新增两个方法：

- `handle_digit(c)`——把 ASCII 数字推入组合串；拒绝英文模式与非数字，与
  `handle_letter` 对称。
- `is_abbreviation_prefix(text)`——当词典中存在拼音键以 `text` 开头**且**含 ASCII
  数字的词条时为真。数字判定正是防止普通拼音词条被误认为缩写键的关键，因此
  `n`/`ni` 永远不会把数字从候选选择那里夺走。

`classify_key` 现在把 `VK_0..VK_9` 映射为 `KeyAction::Digit(char)`，重新成为纯粹的
VK→动作映射；组合感知的门控放在 `plan_action`，与 `-`/`=` 翻页键记录的约定一致。

`plan_action` 在中文模式下按以下顺序裁决数字：

1. 若 `组合串 + 数字` 是缩写键前缀 → `KeyAction::Digit`，进入组合串。
2. 否则，若组合处于活动状态 → `KeyAction::Select(index)`，FR-006 候选选择保持
   不变。
3. 否则 → `None`，放行按键，由宿主插入字面数字。

组合串本身已是纯数字时数字继续累积，因此 `996` 一旦开始输入就能连续键入。
`compose_text`、`sync_engine` 与 `apply_action` 把新增的 `Digit` 变体与 `Letter`
走同一条路径。

## 曾考虑的替代方案

**让数字一律进入组合串，把候选选择改绑其他键。**
否决：FR-006 与 T-040 已验收数字选词，其 VM 验收证据已经归档；为修复一个较小的
行为而回归一个已验收的行为不可接受。

**从 `seed.tsv` 移除这十个含数字键，数字只用于选词。**
否决：这些键是正当的网络语（`996`、`520`、`666`），构建管线已接受并对其把关，
移除会让包与其自身声明的键规则自相矛盾。

**等纯数字串结束后再放行给 slang 查询。**
否决：逐键模型没有"结束"事件，输入法无从知道数字串何时终止；这正是设计文档中
早先的 S-2 草案，它无法在按键路径上落地。

**以"当前无候选"为判定条件，而非词典前缀。**
否决：输入 `9` 之后组合为空且无候选，该条件会把每个数字都送进组合串，破坏字面
数字输入。

## 后果

- 十个含数字缩写键全部可达；`u1s1` 走字母/数字混合路径，`996` 走纯数字路径。
- 成本：数字判定需要每次按键查一次词典，数字因此不再"免费"。该查询是对 mmap
  包拼音索引的二分查找，与每个字母上已经在跑的前缀补全查询同一量级。
- 成本：组合串已是纯数字时会继续接受数字，因此想用数字选词的用户不能正处于数字
  串中间。这是让 `996` 可输入的既定代价。
- `classify_key` 不再承载选择语义；未来任何数字语义改动都应落在 `plan_action`，
  而断言分类结果的单测现在期望 `Digit`。
- 测试：新增五项单测，覆盖前缀识别且不误判拼音词、数字进入后取到缩写词、英文
  模式与非数字拒绝、选择/字面放行语义保持、前缀驱动进入组合。`zhu-ye-ime` 运行
  54 项测试；工作区门禁全绿，host-e2e 的数字选词检查仍通过。
