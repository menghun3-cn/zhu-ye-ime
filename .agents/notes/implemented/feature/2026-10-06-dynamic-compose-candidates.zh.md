# Agent Note: 动态组词候选

Status: implemented

## Problem

2026-10-06 用户报障：输入 `niyou` 只出 `昵友`/`腻友`/`拟游隼`（可用性低），
从不出 `你有`。实测：CC-CEDICT 与 jieba 均无"你有"（`你` r/234587、`有`
v/423765），且现候选路径在**整词命中不足一页**时无组合兜底——`generate_candidates`
的音节切分组合分支仅在**完全无整词命中**时运行。用户确认"机制 + 数据双管"
推荐方案。

## Decision

整词命中不足一页（< `CANDIDATE_PAGE_SIZE`，含整词零命中）且组合串为**完整
音节串**（`segment_all` 恰有一种切分）时，`zhu_ye_core::dynamic_compose_candidates`
按**头部向前贪心最长词匹配**合成唯一候选：每段优先取词库中**最长词**（多音节
词胜过逐音节拼接）、同拼音键取词频最高者、且**跳过整串本身**（整词归属主候选
组）。拼接文本（如 `你`+`有`→`你有`、`我们`+`的`→`我们的`）作为 1 条
`CandidateSource::DynamicCompose` 候选**追加在主候选组之后**（与 FR-058/059
展开组同一插入点语义）、与既有文本去重、按页剩余截断。

不产出：非完整串（还能继续输入，如 `ni`/`nish`）、切分歧义（`xian` →
`xian` 或 `xi`+`an`，宁缺勿误）、音节数 <2、任一段无词。DynamicCompose 候选
**不参与**领域/联系人提权、不进用户词学习。

数据轨：数百条高频口语搭配（`你有`/`你去`/`我来`…）随 T-115 重建管线并入词典，
使常用搭配长期转为整词命中；机制为即时兜底。

## Alternatives considered

- **仅数据搭配表。** 否决：无法覆盖无穷多种常见组合；机制是保证、表是长期稳定层。
- **组词候选置顶（整词命中组之前）。** 否决：D-83 定位于整词命中组之后，既有
  短命中候选排序不变；用户诉求是"出现"，非"居首"。
- **统计/模型内联（n-gram、学习型配对打分）。** 否决：热路径必须离线且确定；
  词典贪心匹配廉价可复现。
- **为已知配对硬编码例外。** 否决：无泛化；词典规则覆盖一切完整串。

## Consequences

- 新增 `CandidateSource::DynamicCompose`（去重、不提权、不学习）；
  `generate_candidates` 行为不变。
- 单次刷新成本：一次 `segment_all` + 至多 `音节数` 次词典查询——有界、离线、
  确定。
- `niyou` 现于整词命中组后产出"你有"；core 与引擎两级单测覆盖；规格 FR-068（§22）。
