# Agent Note: 托盘入口直达工具箱面板（T-169）

Status: implemented

[English](2026-10-18-tray-toolbox-entry.md) | 中文

## Problem

工具箱面板（emoji / 符号，FR-070）只有**一个**入口：常驻托盘进程注册的全局热键
`Ctrl+Alt+E`。界面上没有任何地方提示这个功能存在——不记得热键的用户根本找不到它。
托盘菜单也帮不上忙：当时只有"状态 / 打开设置 / 退出"三项。

用户对照搜狗托盘指出：搜狗有两个可点击的输入法入口（灰线"中"状态图标、橙色"S"
品牌图标），各自点开都有可操作的菜单。真正的缺口不是少一个图标，而是**面板缺一个
鼠标入口**（FR-074）。

## Decision

`zhu-ye-tray` 增加两个鼠标入口，并修正一处陈旧行为：

- **菜单项「工具箱(&T)…」**，位于状态行与「打开设置(&S)…」之间，走与热键相同的
  toggle 路径（全局单面板、按记忆的页签与位置）。
- **双击托盘图标改为开关面板**，不再打开设置窗口。设置窗口保留菜单里可见的条目；
  双击原本是它唯一的隐藏入口，而面板才是用户当前缺的入口。
- **单击即刷新**：左键、右键单击现在都在构菜单前重读 `tray-state`，菜单里的状态行
  与托盘图标不必再等 500ms 轮询。

两条机制保证这件事是安全的：

1. **模态菜单隔离（S-35）**。`TrackPopupMenu` 是模态循环（`WM_ENTERIDLE`），不向调用
   线程分发普通消息。在循环里创建带自己消息泵的面板窗口，面板会收不到绘制与点击消息。
   因此菜单只**收集**命令，所有动作都在 `TrackPopupMenu` 返回**之后**分发。
2. **串行任务队列线程（S-35）**。`PanelWindow` 绑定创建它的线程：`open` 建窗、`Drop`
   销毁。托盘主线程必须保持空闲来跑托盘循环与模态菜单；若每个请求起一个临时线程，
   第二次 toggle 就会撞上正在销毁的窗口。改由**一个长驻工作线程**持有面板：托盘经 mpsc
   投递 `PanelAction::{Open, Close}`，工作线程建窗/关窗、面板打开期间每 15ms 泵一次
   面板自己的消息，并通过 `PostMessage(WM_TASK_DONE, 0, panel_open)` 回报。托盘线程只读
   这个缓存标记来决定"开"还是"关"。

托盘入口的面板可用性：`PanelWindow::listen_escape(1500)` 在最初 1.5 秒内移除
`WS_EX_NOACTIVATE`，让刚唤出面板的用户能按 `Esc` 关闭。鼠标进入面板或定时器到点会调用
`end_escape_window`，恢复"点格即上屏、面板从不抢焦"（S-11 不变）。热键路径完全不接管键盘。

## Alternatives considered

- **单击直接开面板（仿搜狗）**：否决——单击必须保持为稳定的菜单入口（看状态、退出），
  按点击时长猜意图比"左/右键＝菜单、双击＝面板"的分工更不可靠（S-34）。
- **保留双击＝设置**：否决——面板才是用户找不到的功能，设置窗口在菜单里有明确条目。
- **在菜单处理函数里直接建面板**：否决——模态循环屏蔽绘制/点击分发，面板要等到菜单被
  点击结束时才恢复响应，看上去像卡死（S-35）。
- **每个 toggle 请求一个线程**：否决——两次快速请求会在同一窗口上重叠（销毁中途操作），
  且每个线程还要自建面板消息循环。
- **为面板再加一个托盘图标（对齐搜狗的双图标）**：否决——菜单已经暴露全部动作，第二个
  图标只增加点击面不增加能力，且 T-123 已把托盘定成单一方形"中/英"图标。
- **把面板代码搬进托盘进程**：否决——`PanelWindow` 在 `zhu-ye-settings` 库里与设置窗口共用
  （S-31 单面板），复制一份会让渲染代码分叉。

## Consequences

- 面板除热键外有了鼠标入口（菜单项与双击）；托盘外形不变——一个图标、更丰富的菜单。
- `zhu-ye-tray` 从此持有一个贯穿进程生命周期的工作线程。退出与 `WM_DESTROY` 时发送
  `Stop`，线程先 drop 面板（销毁窗口）再返回。线程启动失败时降级为"菜单项与热键在
  `panel-hotkey.log` 写一行错误"，绝不崩溃。
- 双击最多等 1 秒让队列空闲再判断（`wait_panel_state`），因此即使热键 toggle 尚未完成，
  一次双击也只翻转一次；代价只出现在这一罕见的重叠时刻。
- `listen_escape` 会让面板短暂成为前台窗口。面板内任何鼠标活动都会立即结束该窗口期；
  完全不动面板的用户最多承受双击后 1.5 秒的"面板持有焦点"。
- `WM_ENDSESSION` 在注销/关机时移除图标，避免通知区残留幽灵图标。
- "打开设置"现在只能从托盘菜单进入（此前双击也行）。这是有意的口径变化，已写进用户指南。

## Testing

- 单元：菜单命令 ID 互异且有序（工具箱 → 设置 → 退出）；源码契约测试——`TrackPopupMenu(`
  先于每一个菜单动作分发、且中间夹着 `DestroyMenu`；源码契约测试——托盘生产代码里不出现
  `PanelWindow::open`；队列先进先出与按动作去除；队列未启动时投递明确失败。
- 门禁：`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、
  `cargo test --workspace`、`git diff --check`、`scripts/verify-agent-notes.ps1`、
  `scripts/verify-translation-pairs.ps1`。
- 交互项（验收 §23.1）需要真实桌面：菜单内容与顺序、单击即刷新、菜单打开的可用性、
  双击 toggle、与设置窗口的单面板互斥、页签/位置记忆、10 轮快速压力。
