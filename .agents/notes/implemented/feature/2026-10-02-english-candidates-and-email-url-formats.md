# Agent Note: English candidate layer and email/URL formats (scenario 6, M9)

Status: implemented

[中文](2026-10-02-english-candidates-and-email-url-formats.zh.md) | English

## Problem

Scenario 6 (mixed Chinese/English input, FR-030/FR-031) needs an English candidate
layer (misspelled words such as `pytho` → python, `iphon` → iPhone) plus
email/URL format completion (`me@163` → `.com/.cn/.net`, `www.exa` → `www.exa.com`).
The original D-08 plan assumed a hand-curated 10,000-word seed list, which is
impractical to author and audited manually, and D-10 requires English suggestions to
never crowd out Chinese candidates or regress the abbreviation (slang) path that
guards `yyds`.

## Decision

The English word table lives in `zhu-ye-core/src/en_words.rs`, generated by
`scripts/build-en-words.ps1` (cached raw data + pinned hashes; generated file is
committed, never hand-edited):

- Base: FrequencyWords English frequency list (D-018, CC BY-SA 4.0), top 10,000 by
  frequency after ASCII cleaning (a–z plus apostrophe, length 2–32).
- Capitalization: the manual patch table `data/patches/en-capitals.tsv` (D-019)
  restores official forms (`API`/`PHP`/`iPhone`/`QQ`); command-style lowercase words
  (`python`/`java`/`git`) keep lowercase.
- Noise exclusion: `data/patches/en-exclude.tsv` removes Chinese personal-name
  transliterations that are frequent in English corpora (`zhang`/`wang`/`chen` …);
  without this, the prefix `zh` (a pinyin onset every Chinese user types constantly)
  would surface "zhang" as a candidate. Exclusions apply to both the frequency slice
  and the CEDICT supplement.
- Supplement: CC-CEDICT English side (D-001) adds pure single English words
  (parenthesized glosses and multi-word phrases filtered), ranked after the base.

The table stores `norm` (lowercase ASCII key, byte-ascending for `partition_point`)
together with the display case-form `word` and `freq_rank` for intra-group ordering.
`en_words_with_prefix` is case-insensitive and caps its result.

The engine (`crates/zhu-ye-ime/src/input.rs`) appends the English group **after** the
main candidate list and only when the whole composition cannot be segmented into
pinyin (`segment_all` empty, length ≥ 2): Chinese hits are never displaced, `wo`
behaves as before, and a miss cascades to the existing slang/abbreviation path so
`yyds` does not regress. English candidates carry `pinyin = None` and never enter
user-word learning.

Email/URL handling is a deterministic core module `email_url.rs`
(`detect_format`/`email_candidates`/`url_candidates`): an `@` with at least one
character before it selects the email branch (`.com/.cn/.net`, ≤3), and a
`www.` / `http://` / `https://` prefix (case-insensitive) selects the URL branch
(`.com/.cn/.org`, ≤3); a string that already contains a `.` is treated as complete
and passes through as a single candidate. The engine routes on the format kind
before any pinyin path. `handle_format_char` admits `@ . / :` into the composition
while active and returns `false` from an idle state, so `@` never cold-starts a
composition and the host releases it (TSF key routing is covered by T-066).

## Alternatives considered

- **Hand-audited 10,000-word seed**: infeasible volume for manual curation and
  review; replaced by the FrequencyWords-derived baseline plus small human patches.
- **Length-based trigger floor (e.g. ≥3 chars) instead of exclusion list**: would
  sacrifice useful two-letter words (`ok`/`me` support stays); pinyin onsets such as
  `zh` still need real filtering, which only the exclusion list provides.
- **Capitalization guessing**: rejected (D-09) — display the original form from the
  table, never guess.
- **English candidates participating in the main ranking**: rejected (D-10) — they
  are appended after the main list and never influence Chinese ordering.
- **Extending the v2 dictionary format for English words**: rejected — the table is
  sized for an in-crate static slice without format cost.
- **Email/URL candidates reusing the pinyin pipeline**: rejected — a dedicated
  format branch keeps the pinyin path untouched for ordinary Chinese input.

## Consequences

- EN_WORDS has 15,534 entries; ~1.1 MB of generated Rust source adds a small
  compile cost and a hot-path prefix scan bounded by the table slice.
- Segementable English words (`me`, `wo`) deliberately do not trigger the English
  path (D-10: pinyin wins); users wanting a two-letter English word must accept the
  Chinese-syllable hit or use an uncut string such as `mey`.
- Maintaining the tables is additive and low-risk: add entries to the capitals or
  exclusion patches, rerun the build script, and commit the regenerated table.
- The generated file must be kept rustfmt-clean (the script formats it) and the
  `norm` byte order must never be broken, or the `partition_point` query silently
  degrades.
