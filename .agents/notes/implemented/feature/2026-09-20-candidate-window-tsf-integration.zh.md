# Agent Note: Candidate window TSF integration and key interaction for T-013

Status: implemented

[English](2026-09-20-candidate-window-tsf-integration.md) | 中文

## 问题

FR-004、FR-006 与 FR-013 要求候选窗跟随真实组合而不是静态演示：用户要能翻页、切换中英文候选层、切换中英模式，并用数字键选择候选。T-012 已完成渲染，但明确把按键路由、窗口定位与生命周期接线留给本任务。

## 决策

输入引擎用纯 Rust 持有分页与图层状态，TSF 适配层负责按键路由与候选窗生命周期。

`InputEngine` 新增 `CandidateLayer`（中文/译文）、从 0 开始的 `page` 与 `page_size`（默认 9，对应数字键 1-9）。`handle_letter` 与 `handle_backspace` 会把页码重置；`next_page`/`previous_page` 在两端回卷。`toggle_translation_layer` 只有在至少一个候选带非空译文时才进入译文层，因此窗口永远不会出现空白译文页。提交会回到中文层；即使上屏的是译文，学习用户词时也记录中文原词，而 `previous_word` 取实际提交文本用于 bigram 上下文。

`candidate_ui_view` 生成候选窗消费的快照。引擎处于英文模式时视图为空，但组合串仍保留：英文打字期间弹窗隐藏，切回中文后恢复。

TSF 新增四个键动作：Shift 切换模式（忽略 `lparam` 第 30 位标记的长按重复事件，按住 Shift 不会连续切换）、Tab 切换图层、逗号上翻、句号下翻。Tab 与翻页只在中文模式且有活动组合时才被输入法吃下；英文模式下这些键以及字母、Backspace、空格、回车、Esc、数字都放行给宿主。Shift 始终由输入法处理，保证可以从英文模式切回中文。

需要编辑会话的动作先写文本，再用 `ITfContextView::GetTextExt` 取组合范围的屏幕坐标刷新候选窗；纯状态动作不申请编辑会话，刷新时用 `SWP_NOMOVE` 保持窗口当前位置。提交/取消、组合被终止和 `Deactivate` 时隐藏候选窗。

`CandidateWindow` 现在是 TSF 受控弹窗：在宿主 UI 线程创建、更新、隐藏与销毁，不启动自己的消息循环；销毁不会调用 `PostQuitMessage`，演示路径保留单独的退出行为。弹窗位于组合文本延伸区底部下方，并限制在显示器工作区内。

Shift 切到英文模式时候选窗立即隐藏，Tab/翻页/选择不再吃掉按键；切回中文时恢复之前的组合与候选图层。

## 测试

`cargo fmt`、`cargo clippy --all-targets -- -D warnings` 与 `cargo test --workspace` 均通过。新增覆盖：翻页与回卷、基于当前页的选择与预览、输入变化后页码重置、图层过滤、无译文拒绝进入译文层、译文提交语义与学习、模式切换保留组合、英文模式空视图、Shift/Tab/逗号/句号键分类、长按防抖以及英文模式功能键放行。TSF 生命周期测试继续通过：激活/停用、类工厂、拒绝聚合与卸载计数。

T-013 保持“进行中”，直到构建安装到虚拟机并在记事本中验证输入、翻页、图层切换、模式切换、译文提交与弹窗定位。

## 曾考虑的替代方案

**候选窗运行在独立线程。** 落选：独立消息泵会重复实现 TSF UI 线程契约，复杂化 COM 单元规则并增加启动成本；弹窗很轻，在宿主线程重绘即可。

**每次纯状态刷新都通过第二次编辑会话查询位置。** 落选：翻页与图层切换不会移动组合范围，用 `SWP_NOMOVE` 保留上次位置即可，减少 TSF 请求；除非宿主在组合中途滚动，否则可观察行为等价。

**隐藏窗口但保留会抢焦点的工具窗样式。** 落选：必须保留 `WS_EX_NOACTIVATE`，弹窗不能从输入目标抢走焦点。

**提交译文并把译文文本记入用户词。** 落选：用户词频应体现用户选择的中文词；把英文输出记入会污染中文排序库，并影响后续同步与 AI 功能。

**英文模式仍在中文候选列表翻页。** 落选：英文模式按设计冻结组合，功能键应交给应用；此时隐藏弹窗并把键处理还给宿主。

## 后果

M3 候选窗已接入真实组合状态：渲染项、页码、译文层与模式全部来自同一个引擎快照，提交与终止路径会及时移除弹窗。引擎保持平台无关，排序、分页与图层行为在系统集成前由快速单元测试覆盖。

剩余主要风险在真实宿主行为：`GetTextExt` 坐标准确性、同步编辑会话内的弹窗时序，以及与 Windows 快捷键的按键配合仍需 VM 验证。若弹窗位置或刷新时序需要调优，`CandidateWindowPlacement` 边界可以把改动限制在呈现层，不动引擎与 TSF 按键路由。
