# shui 前缀组词展开设计（FR-059，T-090）

> 分类：设计 ｜ 状态：需求已定稿（D-70/D-71 用户确认）、方案定稿 ｜ 关联任务：T-090
> 需求来源：[需求规格说明书 §20](<需求规格说明书.md#20-候选覆盖增强与诊断产品化>)（第十一期，FR-059）。

## 1. 需求与已确认口径

背景：T-060 调研（2026-09-30）扫描 real.zyct，410 个音节中候选不足一页（<9 条）的有
**80 个**（零候选 lue/nue/cei 三个；1-4 个 43 个；5-8 个 34 个）。根因是引擎"完整拼音
整词匹配"口径——候选只来自整串拼音精确命中的词条；主流输入法（搜狗）靠"前缀匹配 + 组词
展开"把拼音以该音节开头的更深词补进首屏。

| 项 | 确认结果 |
| --- | --- |
| D-70 展开时机 | 候选不足一页（<9 条）才展开；整词命中 ≥9 条（常见拼音）逐位不变，T-050 基线零漂移 |
| D-71 展开排序与上限 | 独立追加组，组内按词频取前 N 补足一页；整词命中组序原样保留；eval Top1/Top3 零影响 |

其它硬约束：

- **不动完整拼音 eval 路径**：整词命中/整句/纠错/简拼的触发判定与排序一律不改；T-057
  评估基准（Top1 84.7% / Top3 97.2% / 整句 21.0%）必须零回退；
- 与不完整拼音前缀补全（`generate_prefix_candidates`，FR-023 前缀候选）**边界互斥**：
  本功能只处理"完整音节串"；不完整拼音（`segment_all` 为空）仍走既有补全路径；
- 展开来源覆盖基础包与已启用领域包（Composite 口径），但**不参与领域提权**（D-15 仅
  完整词提权口径不变，见 §5 位次链）。

## 2. 现状与接入点

### 2.1 主候选路径（`crates/zhu-ye-ime/src/input.rs` `refresh_candidates`）

```
组合串 → generate_prefix_candidates（仅不完整拼音触发）         ← 不动
      → generate_candidates（整词优先 / 切分组合）+ rank         ← 不动
          ├ direct_hit：main = 整词命中组（rank 后）
          └ !direct_hit：整句组 prepend + 纠错组 append + 简拼兜底  ← 不动
      → 领域提权 append（D-13，仅 direct 完整词）                  ← 不动
      → 联系人提权 append（D-21）                                ← 不动
      → 英文/缩写/emoji 等尾部组 append                           ← 不动
```

新增插入点：**direct_hit 且 `main.len() < CANDIDATE_PAGE_SIZE(9)`** 时，在整词命中组之
后、领域提权插入点之前追加"前缀组词展开组"。

### 2.2 基础设施

- `Dictionary::lookup_prefix(pinyin)` 已在 `dict` trait、`dict_loader`、`composite`
  实现（二分下界 + 前缀区段扫描，`composite` 各源合并），并有等价性门禁覆盖
  （composite.rs：单词典 vs 复合逐项一致）——展开查询零新增索引；
- `CandidateSorter::sort` 全序（score 降序、同分 text 字典序）已由 proptest 属性门禁
  固化，组内排序直接复用；
- `candidate_from_entry` 的 score 与 `generate_candidates` 同源（词条 score），展开组
  使用同一语义，保证"按词频"表述与既有排序一致。

## 3. core 逻辑：`prefix_expand_candidates`

`crates/zhu-ye-core/src/candidate.rs` 新增纯函数（零 Windows 依赖，可单测）：

```rust
/// 前缀组词展开（FR-059）：对整串拼音做拼音前缀查询，取拼音以 p 开头的更深深词，
/// 过滤与既有候选同文本的条目后按（score 降序、text 升序）确定性排序，截断到 fill 条。
/// 触发判定（完整音节 + 整词命中不足一页）由调用方（引擎）决策；
/// 本函数只做"展开"，任何失败（空输入/无命中）返回空，绝不 panic。
pub fn prefix_expand_candidates(
    dictionary: &dyn Dictionary,
    pinyin: &str,
    fill: usize,
    already: &[Candidate],
) -> Vec<Candidate>
```

流程：

1. `fill == 0 || pinyin.is_empty()` → 空；
2. `dictionary.lookup_prefix(pinyin)` → 条目流；
3. 条目转 `Candidate`（`candidate_from_entry` + `with_source(CandidateSource::PrefixExpand)`）；
4. 过滤：与 `already`（整词命中组文本集合）同文本剔除；展开组内部同文本只保留第一个
   （词条序为文件字节序，第一次出现者即排序前的文本首位，与 `merge_candidate_groups`
    按文本去重语义一致，结论确定）；
5. `CandidateSorter::sort`（score 降序 + text 升序）；
6. `truncate(fill)` 后返回。

**为什么触发判定放引擎**：展开量取决于调用方的主候选条数（`fill = 9 - main.len()`），
core 不持有页大小与候选窗上下文；引擎 direct_hit 分支天然拥有 `main`，判定零成本
（一次 `len() < 9` 比较，对齐 proptest 排序全序门禁）。

## 4. 引擎接入（`zhu-ye-ime/src/input.rs`）

在 `refresh_candidates` 主路径 direct_hit 分支内（`let mut main = rank(...)` 之后、
`!direct_hit` 的整句/纠错分支之前；direct_hit 时该分支本不执行）：

```rust
// FR-059：完整拼音整词命中不足一页时，前缀组词展开补足（D-70/D-71）。
if direct_hit && main.len() < self.page_size {
    let fill = self.page_size - main.len();
    let expanded = zhu_ye_core::prefix_expand_candidates(
        self.dictionary.as_ref(), &self.composing, fill, &main);
    if !expanded.is_empty() {
        let expanded = self.ranking.rank(expanded, &context);
        main = append_group(main, expanded);
    }
}
```

- `page_size` 用引擎页大小（`CANDIDATE_PAGE_SIZE=9`，可测试注入小值）；
- `append_group` 既有语义（组间顺序保持，参与候选窗平铺与翻页）；
- 展开组追加使 `total ≤ 9`（主组 <9 + 展开 ≤ 9-main.len()），第一页即满或更少，翻页
  语义不变；领域/联系人提权组其后追加（total 可能 >9，出现第二页——仅低频音节 +
  领域完整命中同时发生的场景，T-050 常见拼音零影响）。

## 5. 候选位次链（最终顺序）

| 位次 | 组 | 来源 | 说明 |
| --- | --- | --- | --- |
| 1 | 整词命中组 | `generate_candidates` direct + rank | 主排序，eval 基准锚点，**零改动** |
| 2 | 前缀组词展开组 | `prefix_expand_candidates`（FR-059，新） | `main.len() < 9` 时存在；独立来源 `PrefixExpand` |
| 3 | 领域提权组 | `domain_boost_candidates`（D-13） | 完整词命中领域包才出现，插"基础候选（含展开）之后" |
| 4 | 联系人提权组 | `contact_candidates`（D-21） | 与 D-13 同层、在其后 |
| 5 | 尾部追加组 | 缩写/英文/emoji/格式/联想 | 既有语义不变 |

`CandidateSource` 新增 `PrefixExpand` 变体；UI 无新增标签（与 `Static` 等无标签来源
同显），候选窗渲染与既有来源一致（T-043 逐帧基线不回退——组合态候选窗口样不变，
仅内容追加）。

## 6. 确定性 / 测试策略

- **core 单测**（`candidate.rs` 或新 `prefix_expand` 模块）：
  - 种子词典构造含前缀多音节词（如 `shui` → 水/睡 + `shuiping` 水平/`shuijiao` 睡觉），
    `fill=4` → 展开组 = [水平, 睡觉]（score 降序）、已含文本剔除（主组有"水平"则不再出）；
  - `fill=0`/空拼音/无前缀命中 → 空；展开组内部同文本去重；排序确定性（两次调用逐位相等）；
  - 大于 fill 截断；`fill` 大于可用量时全部返回（不满一页）。
- **引擎集成测试**：direct_hit 且 main<9 → 展开组追加、主组序不变；main≥9 → 零追加
  （候选列表与无此功能时逐位一致——用固定种子构造 ≥9 命中音节的对照）；page_size 注入
  小值（如 2）验证 fill 计算；与整句/纠错/简拼/领域/联系人互不干扰（同位次断言）。
- **host-e2e**：`--m14` 断言组（真实词典）——`shui` 展开组含 水平/睡觉 等词且首屏满 9
  条；`de`（高命中音节）无展开（与基线一致）；`nih`（不完整）仍走前缀补全路径断言
  已在既有 `--m9` 或新增对照。
- **eval 回归**：T-057 复跑，Top1/Top3/整句与基准逐位一致（展开组只出现在低频完整
  音节且排在主组之后；eval 语料中这些音节的 Top1 均为整词命中，不受影响）。

## 8. 风险与备选

- **低频音节 + 领域完整命中 → 出现第二页**：可接受（低频音节本来就少词，多一页是功能
  收益）；备选（按需）：展开上限改 `9 - main.len() - 预计提权`，过度设计，不做。
- **lookup_prefix 返回量大**：80 个低频音节中前缀命中词条通常数十~数百，`fill` 截断
  前已过滤去重；单次调用为二分 + 区段扫描，量级与既有简拼/缩写路径一致（µs 级），
  热路径净增可忽略。
- **展开词挤占用户词**：用户词在 `generate_candidates` 中并入主组（direct 命中语义），
  展开组只作补足且排在主组后，不参与用户词学习——学习行为零影响。
- **T-050 基线**：仅 `direct_hit && main.len()<9` 的输入受影响（80 个音节），其余
  逐位一致；验收以 host-e2e 基线断言 + eval 复跑双重把关。
