用户 2026-09-30 确认六项口径（需求 §13.4）：

| 项 | 确认结果 |
| --- | --- |
| D-01 | 任意连续数字即启发式识别（拼音为空时输入数字串直接识别格式弹候选） |
| D-02 | 符号入口用 v 模式（v1→序号、vx→数学符号、vh→常用标点） |

| D-04 | emoji 表内置 300+（首批高频 100，扩展补齐 300+） |
| D-05 | 联想优先：有上屏联想时数字/符号候选不显示，空闲窗单一数据源 |
| D-06 | shui 词汇问题（前缀组词展开）按顺序后置，先做场景 7 |

## 2. 总体架构与复用

三块能力全部落在 `zhu-ye-core`（纯算法、零 Windows API），TSF 层只做键路分发与
文档编辑，与 T-058/059 的职责划分一致：

- **空闲候选窗复用**（T-058/059 建立）：组合串空 + items 非空时显示、定位走
  `selection_placement`、无组合提交走 commit-no-comp 直插、字母/Esc 退出——数字格式
  候选与 v 模式符号候选完全复用这套生命周期，不新增窗口形态；
- **单一数据源原则**（D-05）：空闲窗同一时机只展示一种内容——优先级
  `suggestion（上屏联想）> digit（数字格式）> v（符号）`；有联想则数字/v 不出现；
- **emoji 走拼音态**：不属于空闲窗，作为拼音候选尾追加（与 T-058/059 的联想"不参与
  排序、只占队尾"同构，保证 T-057 基准不回退）；
- 引擎新状态与候选源枚举扩展，`CandidateSource` 沿用既有变体族（新增
  `NumberFormat` / `Symbol` / `Emoji` 三个来源变体，UI 不新增标签）。

## 3. FR-027 数字格式候选

### 3.1 输入交互（对齐主流"边输边上屏 + 选中替换"）

用户输入数字串时数字**立即上屏**（引擎吞下数字键并 commit-no-comp 直插，宿主不再
直通），同时引擎累积 `digit_buffer` 并刷新候选窗；数字串可识别出格式时弹出候选：

- 数字键：追加进 buffer、commit 该数字上屏、刷新格式候选；
- 数字 1-9：上屏选中格式时**替换**刚输入的数字串（删除 buffer.len() 字符后插入格式文本）；
- 空格：上屏选中行（同 1-9 语义）；
- Esc：关闭候选窗、清 buffer（已上屏数字保留，不做替换）；
- 字母/回车：退出数字模式，已上屏数字保留（正常输入了数字 + 后续操作）；
- 连续数字被其它按键打断（如输入 20260930 后按 `年` 拼音）→ 数字模式自然退出。

**为什么"边输边上屏 + 替换"而不是"buffer 暂存"**：主流输入法（搜狗/微软拼音）均边输边
上屏，用户视觉上数字立即出现在正文；若攒 buffer 直到提交，输入 8 位数字期间正文空白，
体验显著偏离主流。代价是替换需要一次文档编辑，见 3.4。

### 3.2 格式识别（core `format_candidates`）

确定性规则，输入串形态 → 候选格式列表（候选 ≤8、按下面顺序确定性排列）：

| 输入串形态 | 类型 | 候选格式 |
| --- | --- | --- |
| 8 位纯数字且 01≤月≤12、01≤日≤31 | 日期 | `2026-09-30` / `2026/09/30` / `2026年9月30日` / `2026.09.30` |
| 6 位纯数字且 01≤月≤12 | 年月 | `2026-09` / `2026/09` / `2026年9月` |
| 4 位纯数字且 1900≤年≤2099 | 年份 | `2026 年` |
| `\d+\.\d{1,2}`（金额） | 金额 | 千分位 `12,345.6` / 中文读数 `一万二千三百四十五点六` |
| 11 位且 `1[3-9]\d{9}` | 电话 | `138 0013 8000` / `138-0013-8000`（原样已在正文，不做候选） |
| ≥5 位纯数字其它 | 纯数字 | 千分位 `12,345` |
| <5 位纯数字或 0-3 位小数 | — | 不触发（返回空，候选窗不弹、不干扰） |

边界与防御：

- 小数部分 >2 位：仍给千分位（只对整数部分），不强行做成金额；
- 超长输入（>32 位）：只给千分位/空，防止候选膨胀与识别打架；
- 纯 0 串、非法日期（20261332）→ 不触发日期，回退纯数字千分位；
- 日期校验失败归入"纯数字"档，保证任何输入都有确定输出（空或最低档）。

### 3.3 中文读数（core `cn_numeral`）

万/亿四位制中文数字转换：

- `12345.6` → `一万二千三百四十五点六`；`10005` → `一万零五`（零处理：内层连续零读
  一个"零"、末尾不读零）；`123456789` → `一亿二千三百四十五万六千七百八十九`;
- 只支持整数(≤64 位) + 至多 2 位小数；负数/超大数不触发；
- 纯算法模块，与位置无关（无 Windows API），单测覆盖零处理与万/亿边界。

### 3.4 替换实现（TSF 层）

引擎对"选择格式"动作返回 ReplaceLast(n, text)：删除文档中最近 n 个字符（=digit_buffer
长度，从当前插入点前移 buffer.len() 位置起）并插入格式文本。TSF 实现：

1. `GetSelection` 取当前插入点（既有 `selection_placement` 通道）；
2. `SetSelection` 定位到 `[insert_pos - n, insert_pos)`；
3. 删除（`DeleteSelection` 或 `SetText("")`）后按 commit-no-comp 通道插入格式文本。

VM 验收重点覆盖：替换后正文无残留数字、光标位置正确、宿主（记事本）兼容。

## 4. FR-028 符号快捷 v 模式

### 4.1 状态机与键路

- **冷启动**：组合为空（空闲态）时按 `v` → 引擎进入 v 模式（`v_buffer = "v"`），
  不走拼音组合（`v` 是合法拼音字符——nv/lv——但只在**空闲态**拦截，组合态照常拼音）；
- **类型码**：`v` 后接 `1-9` / `x` / `h` → 追加进 buffer 并刷新对应符号组候选；
  - 数字键在此态既是类型码（第一键）又是选择键（有候选后）？——设计：只有 `v` 紧接的
    首个字符是类型码；候选出现后数字 1-9 是选择键；
- **回退**：`v` 后接其它字母（如 `vi`，i 非单位键前缀）→ 退出 v 模式，把 `v`+已收码+该字母
  交给正常拼音路径（`vi` → 拼音组合，无候选则维持现状语义；`vmi`+`x` → `vmx`，T-104 不丢已收字母）；
- **Esc**：关闭符号候选、清 buffer 回空闲；空格/数字：上屏选中符号（commit-no-comp 直插）。

### 4.1.1 单位换算整表（T-104，2026-10-05 修订）

v 模式新增第二类类型码：**单位键**（2-8 位小写拼音/英文缩写）：

- **收码**：`v` 后按小写字母，若与某个单位键前缀匹配 → 留在 v 模式继续收字母
  （`vm` → 等待 `vmi`/`vmiao`）；完整键命中出换算候选，前缀未完成不出候选；
- **优先级**：符号类型码（`1-9`/`x`/`h`）只在「等待类型码」（`v` 单字母）时接受；
  单位码进行中字母一律走单位判定——`vs`+`h` 构成 `sh` 不触发标点组；单位键不以
  `x`/`h` 开头，避免与符号码首键冲突；
- **候选**：core 静态表 `units.rs`（`UNIT_CONVERSIONS`，23 键 × ≤9 条），等值换算串
  以该单位为中心（`1 米 = 10 分米`…），确定性表序；来源沿用 `Symbol`（v 模式候选
  整体语义，UI 不新增标签）；
- **上屏**：选中候选 commit-no-comp 直插换算串；
- **数据口径**：SI 倍数精确；市制按通认折算（1 米=3 市尺、1 市斤=0.5 千克、1 市里=0.5 千米）；
  英制/温度等常用近似值（4-7 位小数）固化；温度给定点等价行（0°C=32°F=273.15K）与温差行。

| 键 | 单位 | 键 | 单位 | 键 | 单位 | 键 | 单位 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `vmi` | 米 | `vchi` | 市尺 | `vli` | 市里 | `vmu` | 亩 |
| `vgongqing` | 公顷 | `vsheng` | 升 | `vfang` | 立方米 | `vkg` | 千克 |
| `vjin` | 市斤 | `vliang` | 市两 | `vdun` | 吨 | `vmiao` | 秒 |
| `vshi` | 小时 | `vtian` | 天 | `vshe` | 摄氏度 | `vfar` | 华氏度 |
| `vkmh` | 千米/小时 | `vkb` | 千字节 | `vmb` | 兆字节 | `vgb` | 吉字节 |
| `vdu` | 度 | `vrad` | 弧度 | | | | |

### 4.2 符号表（core 静态表，每类一页 9 个）

| 类型码 | 类别 | 候选（固定顺序，确定性命中） |
| --- | --- | --- |
| `v1` | 序号 | ① ② ③ ④ ⑤ ⑥ ⑦ ⑧ ⑨ |
| `vx` | 数学符号 | ± × ÷ ≈ ≠ ≤ ≥ ∞ ％ |
| `vh` | 常用标点 | ， 。 ！ ？ 、 ； ： “ ” |

符号组初版只做上述三组（不贪全）；表结构支持后续追加类型码（T-104 已追加单位键一类）。

## 5. FR-029 emoji 推荐

### 5.1 匹配与展示

- 拼音组合态（composition 非空）每次刷新候选时查别名表：输入串**整串等于**别名 → 把
  emoji 追加到候选**尾部**，来源 `Emoji`；
- 不参与 `StaticRankingModel` 排序（只占队尾），与普通词语义并存（`ku` → 苦 + 😂）；
- 命中与否不改变既有候选集合/顺序，因此 **T-057 命中率基准不受影响**（实现后复跑 eval 验证）；
- 上屏：commit-no-comp 直插 emoji 字符。

### 5.2 别名表（core `emoji_table.rs` 内嵌）

- 条目格式 `(alias, emoji)`：alias 为拼音全拼或中文关键词（`xiao`/`微笑`→😄），
  emoji 为 Unicode 标准字符（无外部版权数据）；
- 表按 alias 全文字母表排序（确定性），查询用二分；上限 512 条防热路径退化（O(log n)）；
- **铺设节奏**：实现 PR 内置首批高频 100 条；T-062 数据子任务补齐至 300+（纯数据追加，
  不涉及机制）；每批新增条目必须带命中/不命中单测。

## 7. 优先实现顺序（T-061 内部批次）

1. core：format.rs + cn_numeral + 单测（纯算法先行，CLI 可查）；
2. core：symbols.rs / emoji.rs（表首批 100）+ 单测；
3. ime 引擎：状态机与候选源（先 engine 层全绿）；
4. TSF：键路 + 替换；
5. host-e2e `--m9` + workspace 门禁；
6. VM 交互验收（验收标准 9.1 同款流程）。

## 8. 验收

- core 单测：日期/年月/年份/金额/电话/千分位各型命中与边界（非法日期、超长、纯 0）；
  cn_numeral 零处理与万/亿边界；v 三组表；emoji 命中/不命中/并存；
- ime 单测：数字模式全键路（追加/选择替换/Esc 保留/字母退出）、v 模式（冷启动/类型码/
  `vi` 回退）、联想优先（有联想时数字候选不出现）、emoji 队尾追加；
- host-e2e `--m9`：`20260930`→4 日期候选、`12345.6`→千分位+读数、`1[3-9]…11 位`→电话、
  `v1`→①、`vx`→±、`xiao`→😄、`ku`→苦+😂并存、`xyzabc`→无 emoji；
- workspace 全绿 + fmt/clippy/diff-check 门禁；T-057 eval 复跑不回退；
- VM 交互验收（验收标准 9.1）：输 `20260930` 选第 2 个 → 正文 `2026/09/30`（替换无残留）；
  `v1` 数字 1 → ①；输 `xiao` 数字选 → 😄；截图 + TSF 日志取证（vm-accept-sop）。

## 9. 风险与备选

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| TSF 替换链（删 n 字符再插格式）宿主差异 | 数字格式候选核心体验 | VM 多宿主验收；失败回退"buffer 暂存退出补写"方案（备选 A） |
| 空闲态数字键被引擎接管（不再宿主直通） | 若引擎 commit 失败正文丢字 | engine 单测 + host-e2e 断言任何数字键路径必有 commit；超长/异常不吞键 |
| emoji 300+ 表维护成本 | 数据铺设子任务（T-062） | 内嵌静态按字母序 + 单测全命中；首批 100 与扩展分两批 |
| 数字候选窗口期与宿主直通并存时重复上屏 | 正文重复数字 | 引擎吞键 → 单点 commit，宿主无直通，消除双写（设计已消除） |

**备选 A（buffer 暂存）**：数字不进正文、只进 buffer + 候选窗；提交时写格式或退出补写
buffer。实现最简（无需 TSF 替换），但 8 位数字输入期间正文空白、偏离主流体验，故 v1
不采用；仅当替换链在 VM 验收失败时切换。
