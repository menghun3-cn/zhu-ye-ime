## 1. 设计目标与原则

- 第一性原理：每一层只解决一个本质问题，不把"做输入法"简单等价为"组装开源组件"
- 可控优先：核心算法与数据格式完全自研，借鉴成熟模式但保持代码可审计、可替换
- 最小闭环：先用最小 TSF 闭环验证最大风险，再逐步扩展能力
- 可测试：核心算法与 Windows 适配严格分层，算法层可在任意平台验证
- 本地优先：AI 是扩展能力，不进入输入热路径

## 3. 技术选型与理由

| 领域 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Rust 1.98.1（edition 2021） | 内存安全、模块化强、可长期演进 |
| 输入法框架 | TSF（Text Services Framework） | Windows 10/11 官方现代输入法协议 |
| TSF 接口实现 | windows crate（COM 接口手写绑定） | 生态最成熟的 Rust Windows 绑定 |
| 候选窗 | Win32 自绘（GDI/Direct2D） | 依赖最少、延迟可控、便于深色/DPI 适配 |
| 词典加载 | 只读空间 mmap | 冷启动快、内存占用可预测 |
| 词典构建 | 自研管线 | 数据可信、格式可控、免外部依赖 |
| 序列化 | 用户态少量配置用 serde_json | 仅配置与用户词，不用于热路径 |
| 测试 | cargo test + bench | 算法层无 Windows 依赖，可全平台验证 |

不使用 librime、Weasel 等现成输入法内核，避免上游耦合、黑盒行为与不可控体积。拼音音节表、Unicode 表等语言事实采用公开数据生成。

## 4. 模块设计

### 4.1 zhu-ye-core

纯 Rust 库，不依赖 Windows API，对外提供确定性算法。

#### 拼音切分（pinyin）

- 输入：全拼字母串
- 音节表：由数据管线从权威音节数据生成静态表，构建时校验唯一性
- 切分：前缀匹配 + 动态规划，输出所有可行音节切分
- 预留：双拼码表作为可替换配置，第一版不启用

#### 词典（dict）

- 定义 `DictionaryEntry { word, pinyin, translation, frequency }`
- 热路径接口：`lookup(pinyin) -> Vec<DictionaryEntry>`
- 二进制格式：
  - Header（版本、hash、条目数、偏移量表）
  - 拼音前缀索引（紧凑数组/Trie 结构，后续实现细节见架构文档）
  - 词条区（差分编码、定长字段 + 变长文本区）
- 加载方式：文件锁 + 只读 mmap，不反序列化

#### 候选排序（candidate）

- 静态模型：unigram 词频 + bigram 上下文
- 用户权重：`score = 静态分 + 上下文分 + 用户词频加权`
- 排序结果确定性，输入相同则输出相同

#### 用户词（user_dict）

- 记录：词、拼音、使用次数、最近使用时间
- 存储：`%APPDATA%\ai-zhu-ye-ime\user_words.json`
- 损坏恢复：自动备份 `.bak` 后重建空库
- 提供删除词、重置接口

#### 翻译（translate）

- 本地索引在构建词典时与拼音索引绑定生成
- 初版覆盖：中英词汇和常用短语
- 反查：英文词条反查中文
- 未命中：返回空，后续 AI 服务可补充

#### AI 接口（ai）

```rust
pub trait AiService: Send + Sync {
    fn suggest(&self, ctx: &InputContext) -> Vec<AiSuggestion>;
    fn translate(&self, text: &str, direction: TranslationDirection) -> Option<String>;
    fn polish(&self, text: &str) -> Option<String>;
}
```

- 第一版仅 `OfflineAiService`，返回本地基础结果，保证零网络
- AI 候选带来源标识，独立区域展示；普通输入路径绝不等待 AI

### 4.2 zhu-ye-ime（TSF 适配层）

- crate 类型：cdylib，产物为输入法 DLL
- 职责：实现 TSF 输入处理器、管理组合状态、接收按键、请求核心候选、驱动候选窗、执行上屏
- 线程模型：遵循 TSF STA/UI 线程要求，核心调用保持短小；需要耗时的 AI 调用放到后台任务，结果异步回填
- 生命周期：`DllGetClassObject -> TextService -> 焦点/输入状态`；卸载必须完整释放 COM 引用与资源

### 4.3 zhu-ye-dict（数据管线）

- 阶段：下载/登记原始数据 -> 清洗 -> 合并去重 -> 拼音注音 -> 统计词频 -> 编译二进制 -> 生成 hash 与清单
- 每次构建产物记录数据源版本、处理脚本版本、输出 hash
- 大文件原始数据不进入 git；清单与构建脚本进入 git

### 4.4 zhu-ye-cli

| 命令 | 用途 |
| --- | --- |
| `self-check` | 环境、模块、配置自检 |
| `bench` | 对切分、查找、翻译执行基准 |
| `rank` | 按上下文输出排序候选 |
| `eval` | 命中率评测（Top1/Top3/整句） |
| `suggest` | 上屏联想候选 |
| `dict` | 加载 v2 词典查询与反查；`dict update` 转发更新器 |
| `user` | 查看、删除、重置用户词库 |
| `demo` | 纯算法层候选演示，方便无 GUI 调试 |

词典构建与产物检查（`build` / `inspect` / `verify` / `import` / `sign-manifest` / `eval-set` 等）由 `zhu-ye-dict` 提供，不属于本 CLI。

## 11. 词典体系与自动更新

### 11.1 设计目标

1. **运行时零改动候选管线**：多词典通过复合字典（CompositeDictionary）注入现有接口，候选生成/排序/分页/译文层不感知多文件存在
2. **默认离线不被破坏**：唯一网络组件是独立更新器 exe，且在线更新默认关闭（需求 P-03）
3. **可复现构建**：pins 锁定数据源版本与哈希，确定性构建，产物哈希可复核
4. **可控体积**：基础包按词频裁剪进预算（NFR-006），领域包/网络语包 mmap 按需装载
5. **面向更新分发**：词典版本独立于输入法版本，manifest 签名 + 内容哈希双校验，坏包可回滚

### 11.2 总体架构

```text
┌ 构建侧（开发/维护期，可联网）────────────────────────────────────┐
│ data/pins/*.json        数据源锁定（URL + SHA-256 + 版本 + 许可）  │
│ scripts/update-dict.ps1 下载→校验→调用 zhu-ye-dict                 │
│ zhu-ye-dict（新子命令）  清洗→把关过滤→构建 base/it/med/slang      │
│                         →manifest.json→自动登记数据清单/许可      │
└───────────────┬──────────────────────────────────────────────────┘
                ▼ 发布：GitHub Releases（各词典包 + 签名 manifest）
┌ 运行时侧（默认离线）────────────────────────────────────────────┐
│ base.zyct           随安装只读（DLL 同目录 / Program Files）      │
│ it/med/slang.zyct   %APPDATA%\ai-zhu-ye-ime\packs\（可写，更新目标）│
│ 启动装配：读 config.json → CompositeDictionary(base + 启用包)     │
│ 更新：zhu-ye-updater.exe（唯一网络组件）→ 临时区→验签验哈希→原子替换│
└──────────────────────────────────────────────────────────────────┘
```

### 11.3 多词典运行时模型（FR-015、P-12）

- **CompositeDictionary**：实现现有 `Dictionary + BigramModel + Translator` trait，持有 N 个 `DictionaryFile`（各自 mmap 只读打开）
  - `lookup/lookup_prefix`：跨文件合并，同「拼音+词条」去重
  - `frequency`：同词取 **max**（S-6 定稿；bigram 同理取 max）
  - 译文：取非空者（正查/反查索引并集）
- **等价性门禁**：仅启用基础包（无领域包）时，候选输出与现版单词典**逐项一致**（host-e2e 现有断言保持全绿，是回归底线）
- **配置文件**：`%APPDATA%\ai-zhu-ye-ime\config.json`（serde_json，与用户词库同目录）：
  - `{ "enabled_packs": ["it","med","slang"], "online_update": false, "last_check": null }`
  - 未知包 id 忽略并记日志；损坏配置回退默认（仅 base）
- **装载策略**：启动时解析路径列表（installed 基础包只读 + appdata 可写包）→ 依次 `DictionaryFile::open` → 任一包打开失败**跳过该包并记日志，不阻断输入**；绝不半加载（NFR-009）
- **重启生效**（P-12）：config 变更在下次启动时装配，不做热切换
- 包文件命名约定：`<pack_id>.zyct`，v2 格式不变（无需格式升级；格式变更随输入法发版，P-06）

### 11.4 候选合并与缩写输入路径（FR-016/017、P-08）

- 拼音路径：`generate_candidates(table, composite, pinyin)` 原样工作，无需改动
- **缩写路径**（新引擎分支，仅当全部满足）：
  1. 输入串**完全无法切分**（`segment_all` 为空，即非合法拼音组合）
  2. 长度 ≥ 2（S-2 定稿；防单字母泛滥）
  3. 命中 slang 包 `lookup(letters)` 或 `lookup_prefix(letters)`（缩写词条以字母串本身作为拼音键入库，跳过音节校验）
  - 结果作为**独立候选组追加在尾部**，不参与默认排序竞争；候选标注 `[网络]`（候选结构已有 source 字段可扩展）
- **数字混排**：996→"九九六"。数字键语义（T-049 定稿）：中文模式下先判断"组合串+该数字"是否为某含数字缩写键（拼音键含 ASCII 数字）的前缀，是则数字进组合串；否则回落原语义（有候选选词、无候选直出）。判定依赖 `Dictionary::lookup_prefix`，纯拼音词条不会被误判为缩写前缀
- **防污染**：可切分串（如 "wo"）绝不进入缩写路径；缩写组仅在"完全不可切分"时出现，且默认排尾

### 11.5 构建管线（FR-018/019）

- **pins 清单**：`data/pins/<source>.json`，每源一条（URL、SHA-256、版本、许可证、许可义务备注）；构建先校验后使用；教育部官网 http/https 跳转跟随 + `data/cache/` 本地缓存（链接漂移预案，来源仍以官方 URL 登记）
- **数据源映射**（需求 R4 定稿）：

| 产物 | 数据源 | 许可 | 处理 |
| --- | --- | --- | --- |
| base.zyct | CC-CEDICT 120k（保留）+ 现代汉语常用词表 56,008 + 通用规范汉字表 8,105 + jieba 34.9 万 | BY-SA / 官方公有领域 / MIT | 合并去重、按合并词频裁剪（11.6） |
| 词频 | wordfreq zh 33.4 万（主，zipf）+ jieba 词频（第二来源） | 数据 BY-SA 4.0 | 同词取 max（S-6） |
| it.zyct | THUOCL_IT 16,000 + MDN 术语表 ~2,000 | MIT / BY-SA 2.5+ | 简繁归一（OpenCC 思路）、去重、拼音注音 |
| med.zyct | THUOCL 医学 18,749 | MIT | 同上 |
| slang.zyct | 人工种子表（`data/slang/`，带来源注释）+（可选）social-media 高频子集（默认关） | 项目自有 / MIT | **把关过滤**后入库 |

- **把关模块**：构建期统一模块，负面清单（自建，数百条）为构建输入、不进发行包；产物记录"把关表版本 + 正负抽查样例（各 ≥200 条）命中率"（S-3：本期仅作用于 slang 包）
- **可复现**：pins 锁定 → 确定性构建 → `zhu-ye-dict verify-manifest` 复核产物哈希一致；数据清单.md 自动登记（新增/变更行 + 产物 SHA-256），licenses.md 同步许可义务；构建失败显式报错，不产出不完整包

### 11.6 体积与性能预算（NFR-006）

| 包 | 预估 | 控制手段 |
| --- | --- | --- |

# 第三期：输入体验优化方案（M7，已评审）

> 对应需求规格说明书 v0.3.0 第 12 节（FR-023 至 FR-025）与 docs/输入法体验优化.md。
> 方案（2026-10-02）经评审确认，决策 O-01 至 O-06 全部定稿。

## 12. 输入体验优化

### 12.1 设计目标与原则

1. **零词典改动**：三项优化全部落在**解码层**（zhu-ye-core 的切分/候选模块），v2 词典二进制格式、词典包产物与构建管线完全不动（O-06）
2. **补弱不污染**：简拼/模糊音/纠错只在主路径候选**缺失或偏弱**时介入，绝不改变 `wo`、`nihao` 等既有正常候选行为（回归底线：host-e2e 现有断言保持全绿）
3. **确定性**：所有展开顺序、得分、截断都使用固定顺序（音节表序/文本序/词频降序），相同输入必得相同候选
4. **离线零网络**：不引入新数据源、不触发网络；静态简拼音节表与模糊音映射均为语言事实，自研维护（O-01）
5. **性能受控**：简拼展开查询次数、纠错变体数、beam 宽度都有上限，候选刷新延迟门槛 ≤30ms（目标 ≤15ms）不破

### 12.2 简拼/首字母输入（FR-023）

#### 12.2.1 场景与现状

- 场景：`nh`→你好、`wsm`→为什么。现有缩写路径（M6-R）只查网络语包，`nh` 这类无法命中；`generate_prefix_candidates` 对无完整音节开头的输入（`nh` 中 `n`/`h` 都不是完整音节）两组皆空，主候选为空。
- 目标：不可切分的纯字母短串（2-4 位）按首字母展开整词，命中常用词作为**主候选**参与排序。

#### 12.2.2 简拼音节表（静态常量化）

内置 `INITIAL_SYLLABLE_TABLE: &[(char, &[&str])]`，每个 ASCII 小写字母对应 4-6 个**最常用**音节（语言事实，按口语常用度人工排序；非数据源，无需许可证登记）：

```text
n → [ni, na, nan, neng, nian]
h → [hao, he, hai, han, hui]
w → [wo, wei, wan, wang, wen]
s → [shi, shen, sheng, sui, suo]
m → [me, ma, ming, men, mu]
...（其余字母同法，未列字母无简拼）
```

#### 12.2.3 展开算法

输入不可切分串 `initials`（纯 ASCII 小写字母，长度 2-4）时：

1. 每个字符查表得音节候选集 `S_i`（某字符无表项 → 简拼放弃，返回空）
2. 对 `S_0 × S_1 × ...` 做**前序笛卡尔积**（表序即常用度序，保证确定性），逐个拼接成完整拼音串 `p`，`dictionary.lookup(p)` 精确查词条
3. 命中的词条转候选（`CandidateSource::Static`），参与正常排序；拼接串保留为 `pinyin`（供用户词学习）
4. 数量上限 `INITIAL_COMPLETION_CAP`（32）；组合数 = ∏|S_i|，2 位 ≤36、3 位 ≤216、4 位 ≤1296 次 lookup，热路径受控（微秒级 × 数千次仍 <1ms，且有 cap 截断兜底）

**防污染**（O-02）：

- 单字符不触发（长度 <2）；长度 >4 不触发
- 输入含数字或非小写字母不触发（与缩写路径判据互补：缩写路径管「含数字/ASCII 混排」）
- **完全可切分串绝不进入**（`wo`/`nihao` 走正常全拼，`segment_all` 非空即短路）——用 `is_abbreviation_input` 同款三重门槛复用（长度 ≥2 + 纯小写字母 + `segment_all` 为空；但**排除数字**，避免与 T-049 数字缩写语义纠缠）
- 简拼只在**主候选为空**时启用（`generate_prefix_candidates` 两组皆空且缩写无果时），产出作为主候选

#### 12.2.4 接口

```rust

pub const INITIAL_MAX_LEN: usize = 4;
pub const INITIAL_COMPLETION_CAP: usize = 32;

    table: &SyllableTable,      // 未实际使用，保留签名对称性可去掉
    dictionary: &dyn Dictionary,
```

### 12.3 模糊音与纠错（FR-024）

#### 12.3.1 场景与现状

- 场景：`zongguo`（z↔zh）→中国；`niha`（ha→hao 少字母）→你好；`fag`（f↔h、ang）→发。
- 现状：`zongguo` 可切分但无整词命中，只出「宗国」等音节拼接垃圾；`niha` 切分为 `ni+ha` 出「你哈」。均无纠错。

#### 12.3.2 模糊音映射表（静态）

双向等价组（O-03，覆盖文档 7 组枚举）：

```text
声母: zh↔z, ch↔c, sh↔s, n↔l, f↔h
韵母: an↔ang, en↔eng, in↔ing
```

#### 12.3.3 两类纠错

**A. 模糊替换（打错音节）**：`fuzzy_variants(syllable) -> Vec<String>` 对单个音节应用全部映射替换（每音节变体数有限：声母/韵母替换最多各 1 处，变体数 ≤ 组合数小常数）。整串生成变体时**只允许单处替换**（任一音节替换一次），避免组合爆炸：`zongguo` → `zhongguo`、`zongguang`(无效)…

**B. 少字母补全（打快）**：对完整切分结果的**最后一个音节**，枚举所有「以它为前缀的完整音节」（如 `ha`→`hao/han/hang/hai`…），逐个替换后整串 lookup：`niha`（ni+ha）→ `nihao`→你好、`nihan`→你憨、`nihang`…

**触发条件**（补弱）：

- 输入串**可完整切分**且**无整词命中**（`dictionary.lookup(pinyin)` 为空）时启用
- 变体拼音串 lookup 命中的词条标注 `CandidateSource::Corrected`，作为**独立「纠错组」追加在主候选之后、缩写组之前**（UI 不新增标签，与 `[网络]` 区分仅靠 source 字段；行为与搜狗「猜你想输」同构）
- 变体上限 `CORRECTION_VARIANT_CAP`（24），全串替换位置只取声母/韵母映射可行的位置
- 结果确定性：映射表顺序固定、变体按出现顺序遍历、同类得分相同按文本序

#### 12.3.4 接口

```rust
// candidate.rs
pub const CORRECTION_VARIANT_CAP: usize = 24;
pub fn corrected_candidates(
    dictionary: &dyn Dictionary,
    pinyin: &str,
) -> Vec<Candidate>;   // source=Corrected；不可切分/整词命中/空输入返回空
```

### 12.4 整句/长句输入（FR-025）

#### 12.4.1 场景与现状

- 场景：`woxiangmingtianqubeijing` → 我想明天去北京。
- 现状：`generate_candidates` 对多音节无整词时，每个音节只取 `lookup(syllable).first()`（最高频第一词）拼成一句，不做全局寻优；`xiang` 若首词是「响」就整句错。

#### 12.4.2 Beam Search 解码

实现要点（M7-A 实测修订，2026-10-02）：

- **位置枚举跨音节整词**：在每个拼音位置 `cur` 枚举所有「可完整切分的子串」
  （1 至 `SENTENCE_MAX_WORD_CHARS=12` 字符，即最多 4 个音节），直接
  `lookup(sub)` 命中词典——`mingtian` 这类两音节整词可被选中。第一版本设想
  的"逐音节只查单音节"实现选不出跨音节整词，已废弃。
- **评分（词间转移建模，不再逐项相加）**：
  - 首词：`min(词频, 100_000) × unigram_weight`；
  - 后续词：前词→本词 bigram 有证据（>0）时
    `min(词频, cap) × unigram_weight + min(bigram, 100_000) × bigram_weight`；
  - **无 bigram 证据（频率=0）时 `min(词频, cap) × unigram_weight − SENTENCE_BIGRAM_MISS_PENALTY`**，
    罚额=unigram 上限（100_000），保证无证据词贡献 ≤0。
- **为何修订**（真实词库 `woxiangmingtianqubeijing` 实测）：初版"unigram 无上限
  + bigram 相加"与"罚额 < cap"都失败——超高频介词单字（如「被」）词频远超整词
  （「北京」unigram 仅 1088），罚后残值仍为正，两个残值相加即可压过低频整词，
  beam 退化为逐字拼接。unigram cap + 罚额=cap 后，无证据拼接路径整体必然深于
  有证据路径，「我想明天去北京」稳定居首。
- **完成路径跨轮保留**：整词步长（如「明天」8 字符）会让高分局提前到达串尾；
  若只从当轮 `new_beam` 收集，逐字慢路径会在后续轮次把提前完成的路径挤出
  beam。实现用独立 `completed` 集合跨轮累积（同样按分截断到 `BEAM_WIDTH`），
  输出时与未完成路径合并去重。
- beam 状态 `(Vec<String> 词序列, 消耗位置, 累计分)`；每步至少消费 1 字符，
  保证 ≤ len 轮终止；每轮展开后按累计分降序截断 `BEAM_WIDTH=8`，同分按词文本序。
- 输出：消耗位置 == n 的路径（未完成路径不输出），同文本去重取最高分，
  返回前 `SENTENCE_TOP_N=5`；整句文本拼接词序列，pinyin=整串，source=Static。

- **整词优先不变**：输入存在整词命中（`nihao`）时主路径直接给词，不启动 beam（`generate_candidates` 原行为保留）
- **回退安全**：某音节无任何整词命中或全部路径耗尽时，回退到现状「每音节首词拼接」保证 ≥1 候选（O-04）

#### 12.4.3 与主候选融合

整句候选作为**独立「整句组」置于主候选最前**（长串用户意图就是整句），随后是单音节词/普通候选（现状），然后纠错组（12.3），最后缩写组（M6-R 现状）。组间顺序固定、组内确定性排序。

#### 12.4.4 接口

```rust
// candidate.rs
pub const BEAM_WIDTH: usize = 8;
pub const BEAM_WORD_CAP: usize = 4;   // 每个子串最多参与搜索的候选词数
pub const SENTENCE_TOP_N: usize = 5;
pub const SENTENCE_MAX_WORD_CHARS: usize = 12;  // 单个词最多覆盖的拼音字符数
pub const SENTENCE_UNIGRAM_CAP: i64 = 100_000;  // 整句评分的单字词频上限
pub const SENTENCE_BIGRAM_MISS_PENALTY: i64 = SENTENCE_UNIGRAM_CAP; // 无 bigram 证据惩罚
pub fn sentence_candidates(
    table: &SyllableTable,
    dictionary: &dyn Dictionary,
    bigram: &dyn BigramModel,
    pinyin: &str,
) -> Vec<Candidate>;   // 音节数 <3 / 整词命中 / 空输入返回空
```

### 12.5 候选融合流程（InputEngine.refresh_candidates 改造）

```text
输入 composing
├─ 可完整切分（segment_all 非空）?
│   ├─ 是 → 主路径（现状前缀/整词逻辑）
│   │      ├─ 整词命中 or 音节数 <3 → 现状结果
│   │      └─ 音节数 ≥3 且无整词 → 整句组(12.4) + 单字/词候选
│   │      └─ 无整词命中 → 追加纠错组(12.3)
│   └─ 否（不可切分）→
│         ├─ 缩写路径（M6-R，slang 包精确/前缀）→ 尾部独立组（现状）
│         └─ 主候选为空 且 纯字母 2-4 位 → 简拼展开(12.2) 作为主候选
└─ 统一去重（同文本取最高分）+ 组间固定顺序 + Clyde 排序（现状 CandidateSorter）
```

### 14.3 中英混合整句解码（FR-050）

#### 14.3.1 触发与判别

- 输入串**同时含可拼音切分的段与不可拼音切分的连续字母段**（如 `python代码`：
  `python` 不可切、`代码` 可切）→ 进入混合串解码；纯拼音/纯字母串走既有路径
  （D-55/FR-030 不回退）
- 字母段边界 = 连续 `[A-Za-z]` 游程；数字/符号/中文切分段边界（复用 FR-027 的
  结构化文本识别边界，TSF 键路不新增特殊键捕获，D-11 模式）

#### 14.3.2 确定性解码算法

- **字母段**：整段对英文词表贪婪匹配——先查全段（`python`），未命中逐前缀减一
  重查（确定性、自研、O(len²) 上界但有候选上限约束）；命中即原形大小写
- **其余段**：进入既有全拼切分（T-007）+ 候选排序（T-008/T-055）
- 混合判定规则（core 侧，纯函数）：`is_mixed(input) = 存在可拼音段 ∧ 存在不可切
  字母段(长度≥2)`；单段输入不经混合路径
- 不引入统计模型/语言模型（D-56，14.3 非目标保持）

#### 14.3.3 整句候选 + 分段候选

- **整句候选**：混合串整体作为 1 个候选置首（`python代码`），来源标注"混合"
- **分段候选**：后续列出各段的最优候选组合（`python` / `代码`），数量与上限沿用
  候选组约束；分段内英文候选规则同 FR-030
- 排序：整句组 → 中文字段候选（既有排序）→ 英文段候选（词频）；确定性；与既有
  候选窗渲染（候选窗不区分内容语言）零改动（D-57）

#### 14.3.4 上屏交互

- 数字/空格选整句候选 → 整句上屏（`python代码` 整体已选）；选分段候选按既有
  逐段上屏逻辑
- 上屏后无额外状态（不残留混合态）；取消/退格回退到常规路径
- TSF 键路：无新增键捕获；仅候选选择逻辑扩展（core `InputEngine` 层）

#### 14.3.5 与既有边界（不回退清单）

- FR-017 缩写组（`yyds`）不被混合解码劫持（缩写长度≥2 且全字母、无拼音段 →
  走缩写路径）；FR-030 英文回退（纯字母串）不走混合路径
- 中文 eval/候选排序：混合解码仅在有"不可切字母段"时介入，纯中文输入零影响
- 邮箱/网址（FR-031 `@`/`www.`）识别优先级高于混合解码（结构化文本先判）

### 14.4 网络语扩充（FR-047）

- **源**：social-media-chinese-words（MIT，107.7 万条）→ 清洗出高频子集约 1 万
  （D-52）+ 人工种子表持续扩充（P-08/P-14，带来源注释随发版）
- **清洗规则（确定性）**：内容为纯 CJK 或 CJK+字母数字的短语；去重（同形同义仅
  保首现）；过滤敏感违规词（种子表+黑名单词素）；长度 2-12 字符；过滤纯数字；
  过滤与既有字典/用户词完全重复（权重并入既有项不新增）

  频次列）或语料内置频段截取前 1 万；确定性可复现（记录清洗脚本 SHA）

  social-media-zh 锁定，D-020）；`zhu-ye-dict social-clean` 清洗规则 v1（词形=汉字+

## 15. 第十二期方案（M15）

### 15.1 设计目标与原则

- **安装语义零改写**：exe 安装包只是既有 `install.ps1`/`uninstall.ps1` 的产品化外壳
  （D-74），版本化 DLL、导出校验、TSF 注册回滚、预置包、快捷方式、延迟清理全部复用，
  避免为新外壳重写核心安装逻辑引入回归风险
- **镜像优先**：更新源必须用**不受 GitHub latest 语义影响**的稳定 URL（D-76）；
  镜像与更新包同快照发布，杜绝"官网与更新源版本漂移"
- **解耦部署**：更新源镜像与官网站点**分离托管**，避免"官网重部署覆盖更新源资产"
  的持续性陷阱（详见 15.3 对抗性审查）
- **确定性可验**：发布流水线每一步可复现（pins/签名/verify 既有门禁保持），新增
  exe/Pages 步骤同样纳入 e2e；online_update 默认关闭不变（D-77），隐私面零扩大
- **不回退**：T-057/T-090 的中文候选排序基准与 host-e2e 全量断言不受本批影响

### 15.2 exe 安装包（FR-061）

#### 15.2.1 形态与工具链

- **Inno Setup 6**（免费、可商用、CI 可装）：`ISCC.exe` 编译 `.iss` 脚本 → 单文件
  `ai-zhu-ye-ime-setup-<ver>.exe`（x64，`ArchitecturesInstallIn64BitMode=x64compatible`）
- 本机无 ISCC：CI（windows-latest）用 `choco install innosetup`；本地开发用
  `scripts/build-setup.ps1`（首次自动下载 Inno Setup portable 到 `target/tools/`，
  不污染系统，路径可复现）
- 无 Authenticode 签名（D-75）：`[Setup] SignTool=` 留空；`build-setup.ps1 -SignCommand`
  参数预留（后续有证书时填 `signtool.exe sign /f …` 即出签名包）

#### 15.2.2 安装流程（外壳 + 复用语义）

```
Inno 向导（欢迎/许可/安装目录/准备安装/安装中/完成）
  ├─ 载荷 = 与便携 zip 相同的 package 文件树（bin/scripts/packs/docs），
  │    Files 段释放到 {tmp}\package（Inno 内置 LZMA2 压缩）
  ├─ 安装中：静默调用既有语义（Pascal 无重写）：
  │    powershell -ExecutionPolicy Bypass -File {tmp}\package\scripts\install.ps1
  │      -SkipBuild -PackageRoot {tmp}\package ...
  │    （install.ps1 自带 Test-Admin/TSF 注册回滚/版本化 DLL；Inno 仅负责
  │      UAC 提权、UI 与文件释放；进度由 install.ps1 的 Write-Progress 呈现）
  ├─ 安装完成页：显示安装目录、提示开始输入
  └─ 卸载：Inno 卸载器 → 调 uninstall 语义（Remove-TsfRegistration + 目录/残留清理），
       %APPDATA% 用户数据保留（重装不丢词库）
```

- 版本检测：注册表 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\竹叶输入法`
  （Inno 默认写入 `AppVersion`），同版本覆盖安装幂等（Install.ps1 先测后写）
- 安装目录：默认 `Program Files\ai-zhu-ye-ime\`（与 install.ps1 默认一致）；允改
- exe 产物进发布：`assemble-release.ps1` 增加步骤 7"build-setup"，`release.yml` 上传
  exe 为第 7 项资产；下载页直链（FR-063 联动）

#### 15.2.3 安装包与便携 zip 的一致性

- 载荷**同源**：`package-portable.ps1` 的 staging（bin/scripts/packs/docs）同时供给
  zip 与 Inno 载荷；`build-setup.ps1` 直接读该 staging 目录，保证 zip/exe 内容一致
  （同一 manifest/词典/引擎二进制，哈希一致可复核）
