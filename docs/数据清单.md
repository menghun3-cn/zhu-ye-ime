## 清洗规则

`zhu-ye-dict import` 按以下顺序处理（实现见 `crates/zhu-ye-dict/src/import.rs`）：

1. 行解析：识别 `简体词 [拼音] /译文/` 结构，兼容官方空格分隔与旧制表符分隔；注释与空行跳过
2. 词形：简体词必须是纯 CJK 统一表意文字，排除数字、拉丁字母与符号词条
3. 拼音：按空格与撇号分音节，去声调数字，`ü`/`u:` 归一化为 `v`，输出与引擎一致的连续全拼键
4. 音节校验：每个音节必须命中内置 410 个标准全拼音节表；未知音节丢弃并输出前 20 个样本
5. 字数校验：音节数必须等于汉字数
6. 去重：同词且同无调拼音只保留首个词条
7. 词频：命中 FrequencyWords 的词条取真实计数；未命中按 1，保证常用词仍由词频主导
8. bigram（可选 `--bigram 语料路径`）：每条语料行视为独立上下文；仅纯 CJK 的空白分词参与统计；按词典最长匹配拆词（最多 8 字），未命中字符断开上下文；相邻有效词形成词对，计数截断到 v2 字段允许的 u32 上限
9. 编译：清洗后的词条与 bigram 通过 `build_v2` 生成 v2 二进制词典

## 2026-09-29 词典更新分发（T-051，M6-U）

- **信任链**：manifest 用 ed25519 签名；签名对象是**规范化 JSON**（紧凑序列化且排除 `signature` 字段自身），因此重排键序与缩进不影响签名有效性。客户端信任锚是**编译内置公钥**，manifest 内嵌公钥仅作审计——单测证明攻击者用自己密钥重签会被内置公钥拒绝
- **落地流程**：验签 → 逐包校验内容 SHA-256 与大小 → staging 目录 → **原子替换**（目标同目录临时文件 + `rename`）→ 清理 staging；旧版保留 `.bak`，`rollback_pack` 支持"应用后启动失败"回滚。任一环节失败保证旧版可用，不做部分接受
- **分发范围**：`DISTRIBUTABLE_PACK_IDS = ["it","med","slang"]`。基础包随安装只读交付、`real`/`seed` 为开发期产物，均不参与在线更新——实测发现缺少此约束时更新器会去拉取不存在的发布文件并得到 404
- **更新器形态**：`zhu-ye-updater` 独立二进制（唯一联网组件，S-4），`status`/`check`/`apply`；TSF DLL 在宿主进程内不联网；默认关闭时零网络请求；下载使用系统自带 `curl.exe`（Windows 10+），故不引入 HTTP/TLS 依赖栈；执行完即退出，无驻留进程
- **密钥管理**：签名工具 `zhu-ye-dict sign-manifest` 从环境变量 `ZHU_YE_RELEASE_SECRET_KEY` 读私钥（不经命令行参数，避免留在进程列表与 shell 历史）；客户端公钥经构建期 `ZHU_YE_RELEASE_PUBLIC_KEY` 内置；未内置公钥时更新器拒绝应用任何更新
- **端到端实测**（本地静态服务 + 独立 APPDATA 沙箱，9 项）：正常更新（it/med/slang 三包下载、验签通过、应用成功、staging 清理）/ 重复 apply 识别已最新 / 包篡改重下并建 `.bak` / 签名篡改整体拒绝且已装包未动 / 半包被内容哈希拒绝 / 断网 404 明确失败 / 版本门槛跳过（`min_engine=99.0.0`）/ 默认关闭零网络 / 无驻留
- **测试**：core 新增 13 项 manifest + 12 项 update，更新器 2 项默认关闭断言；工作区 317 项全绿
