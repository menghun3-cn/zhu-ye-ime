## 1. 背景

用户长期使用搜狗输入法，痛点如下：

- 功能臃肿、体积与内存占用持续膨胀
- 频繁弹广告、诱导安装无关软件
- 输入体验被商业行为绑架，无法审计

因此需要自研一款 Windows 输入法，目标是轻量、干净、快速、无广告，并把"中英翻译"直接集成进输入候选区，让用户在输入中文时随时可以选择上屏中文或译文。

## 2. 产品定位

竹叶输入法是一款面向 Windows 10/11 x64 的开源中文全拼输入法，以本地优先、可插拔 AI 能力为设计边界，第一版强调：

- 普通的日常中文输入体验完整可用
- 候选区内置中英翻译，支持一键上屏译文
- 默认离线运行，不采集、不上传输入内容
- 架构上为 AI 翻译、润色、联想、预判、建议预留统一接口

## 3. 项目目标

1. 提供可安装、可卸载、可审计的 Windows TSF 输入法
2. 中文全拼输入体验达到日常可用标准
3. 本地词典翻译覆盖常用词和短语，未覆盖内容后续由 AI 扩展补齐
4. 核心算法全部自研，仅借鉴成熟模式；开放数据作为种子词库
5. 建立完整的文档、任务清单、验收标准与自动维护机制

## 4. 非目标（第一版不交付）

- 双拼、五笔、郑码等非全拼输入方案（架构预留，不作为第一版范围）
- 云同步、账号体系、皮肤商城
- 语音输入、手写输入
- 默认开启的在线机器翻译
- 兼容 Windows 7/8 或 32 位系统
- 面向普通消费者的正式分发与代码签名
- 广告、商业化行为

| 编号 | 场景 | 说明 |

## 6. 功能需求

### FR-001 全拼中文输入

系统接收全拼字母串，完成拼音音节切分与候选生成，支持空格上屏第一候选、数字键选择候选、翻页。

### FR-002 候选排序

候选排序使用离线统计的静态模型（unigram + bigram），并在用户学习后叠加用户词频加权。排序过程必须本地、确定性、可测试。

### FR-003 用户词学习

用户选择某个候选时，本地持久化该词的使用记录；支持用户删除词、重置用户词库。用户词库不得自动同步网络。

### FR-004 中英模式切换

单击 Shift 在中英文模式之间切换。中文模式产出中文候选；英文模式直接上屏英文字母。

### FR-005 中文候选附译文

中文候选行右侧以弱化样式展示对应英文译文，不挤占主候选位置。

### FR-006 译文层

按 Tab 进入译文层，候选列表切换为英文译文；再次按 Tab 或上屏后返回中文候选层。

### FR-007 本地翻译引擎

第一版翻译来自本地词典索引，离线可用。命中中文词条时同步返回译文，支持中英与英中反查。

### FR-008 AI 能力扩展接口

核心层定义 AI 服务接口，能力包括：翻译、整句润色、智能联想、预判、建议。第一版不内置运行时 AI 调用；后续实现通过网络/本地模型接入，默认关闭，结果必须标记来源。

### FR-009 候选窗渲染

候选窗使用 Win32 自绘，支持系统浅色/深色主题、DPI 感知、高对比度模式，文本不模糊、不重叠。

### FR-010 安装与卸载

第一版提供开发者安装/卸载脚本，负责 TSF DLL 注册、注册表写入与清理；卸载必须可完整还原，不留后台进程。

### FR-011 性能与资源

候选刷新、内存占用、冷启动满足验收标准中的量化指标；词典采用 mmap 只读加载，不反序列化。

### FR-012 隐私与网络

在线功能默认关闭时，程序不得发起任何网络请求；所有日志、用户词库仅写本机。第三方数据许可证必须记录在文档中。

### FR-013 共存与兼容

输入法可与其他已安装输入法共存，通过系统语言栏/输入法切换器切换；不得破坏其他应用的输入状态。

### FR-014 可诊断性

提供 CLI 自检、词典检查、性能基准命令；日志分级可控，便于定位问题而不打扰正常使用。

## 7. 非功能需求

### NFR-001 性能指标

| 指标 | 要求 | 目标值 |
| --- | --- | --- |
| 候选刷新延迟 | <= 30ms | <= 15ms |
| 词典常驻内存 | <= 100MB | <= 50MB |
| 冷启动首次出候选 | <= 300ms | <= 200ms |
| 后台驻留进程数 | 0 | 0 |
| 在线关闭时网络请求 | 0 | 0 |

### NFR-002 可靠性

输入法进程内异常不得导致宿主应用崩溃；必须对输入状态做防御性校验；用户词库损坏时自动备份恢复。

### NFR-003 安全性

输入内容默认不离开本机；未来 AI 联网能力必须由用户显式开启，并且请求内容对用户可见。

### NFR-004 可维护性

代码按 crate 分层，核心算法不依赖 Windows 专有 API；公开模块提供 rustdoc；关键算法配套单元测试与基准测试。

### NFR-005 许可合规

所有第三方数据、字体、代码的许可证与来源记录在 docs/licenses.md；发布前必须完成许可审查。

## 11. 词典体系与自动更新

### 11.1 背景与动机

现状（2026-09 盘点）：

- 运行时只加载**单一词典文件** `dictionary.zyct`（`data/artifacts/real.zyct`，120,028 词条 / 820,368 bigram / 约 30MB）
- 数据源仅 3 个（CC-CEDICT、FrequencyWords、OPUS GlobalVoices），词频命中率仅 **23.44%**
- 构建为手动流程：下载 → SHA-256 登记（docs/数据清单.md）→ `zhu-ye-dict import`
- 清洗规则仅接受**纯 CJK** 词条且拼音必须命中 410 音节表，网络用语（"内卷"可过、"yyds/emo/996"全丢）
- 用户习惯词典已有本地运行时学习（UserDictionary + UserDictStore），但不在本次范围内（见 D-06）

用户痛点定位（Q1 确认）：

1. **覆盖率不足**：日常与专业场景大量词打不出
2. **更新繁琐**：数据源手动维护、无一键更新
3. **缺分类体系**：常用 / 专业 / 网络语全部混在一个大池子里，无法按需启用

### 11.2 本期目标

1. 建立「基础常用词库 + 领域词典包 + 网络常用语词库」的分层词典体系，用户可**勾选启用/停用**领域包
2. 提供**一键自动构建与更新**能力：数据源获取、校验、清洗、构建、登记全流程可复现
3. 作为输入法平台方向**终端用户自动分发词典更新**（在线更新，遵循默认关闭原则，见 FR-020）
4. 显著提升常用词覆盖率与排序质量（词频命中率基准 23.44%，目标值待 P-10 确认）
5. 性能指标与"默认离线、零网络请求"原则**不劣化**（NFR-006、NFR-010）
6. 所有新增数据源保持来源、许可证、哈希可追溯（NFR-008）

### 11.3 非目标（本期不做）

- 大语料（维基语料等）自统计词频/分词——留待下一阶段（D-05）
- 用户习惯词典的运行时学习机制改造/导出/同步（D-06，保持现状）
- 云同步、账号体系、皮肤商城（沿用第一期边界）
- 后台常驻更新服务、推送式实时更新（更新检查必须轻量，详见 FR-020 待决策项）

# 第三期：输入体验优化（M7，需求已确认）

> 本节为第三期需求（已确认，2026-10-02）。对应 docs/输入法体验优化.md 列出的常用场景 2（简拼）、场景 3（模糊音纠错）与场景 4（长句整句）。
> 目标是把输入法从"能打字"提升到"懂用户想打什么"，核心指标为首选词准确率与整句准确率。
> 严格遵守第一期"全部离线、自研、确定性"原则：不引入网络/词典新数据源，仅复用现有音节表 + bigram + 用户词基础设施。

## 12. 输入体验优化

### 12.1 背景与动机

输入法体验优化文档（docs/输入法体验优化.md）盘点后，当前实现相对搜狗类输入法有三项核心缺口，直接拉低首选词与整句准确率：

1. **简拼/首字母输入缺失**：文档场景 2 要求 `nh`→你好、`wsm`→为什么；现有缩写路径仅查网络语包，`nh` 这类可对应常用词的首字母组合完全不出候选，需逐字全拼。
2. **模糊音与纠错缺失**：文档场景 3 要求 `niha`→你好、`zh/z、ch/c、sh/s、n/l、f/h、an/ang、en/eng、in/ing` 映射；现有实现中尾部残缺音节（如 `niha` 的 `ha`）在词条补全组只命中以 `niha` 整串为前缀的词，打错、打快、少字母都无法纠错出候选。
3. **整句输入只取每音节首候选**：文档场景 4 要求 Beam Search + n-gram；现有 `generate_candidates` 对多音节串只取每个音节字典首个候选拼成整句，不做 beam 搜索，长句基本不准。

### 12.2 本期目标

1. 简拼输入可用：常用词的首字母组合（≥2 位）出候选，且不污染正常全拼路径
2. 模糊音纠错可用：尾部残缺音节与易混音节打错打快均能纠错出正确候选
3. 整句输入准确率显著提升：多音节输入经 Beam Search 选出全局最优词语组合
4. 全程离线、确定性、可测试；性能指标与"默认零网络"原则不劣化（沿用 NFR-006/NFR-010 门槛）
5. 不引入任何外部数据源；不破坏现有全拼/前缀/缩写/用户词路径

### 12.3 非目标（本期不做）

- 中英混输解码（文档场景 6，依赖英文词库，留待后续）
- 数字/符号/emoji 推荐与格式候选（文档场景 7）
- 通讯录/人名地名本地个性化（文档场景 9，依赖系统通讯录访问）
- 场景自适应（聊天/搜索/代码，文档场景 11）
- 云 + 本地结合、多设备同步（文档场景 12-13，默认离线原则不妥协）
- 神经网络语言模型（本期以整数 bigram 模型为主，保证跨平台确定与零额外依赖）

### 12.4 已确认决策

| 决策 | 内容 | 备注 |
| --- | --- | --- |
| O-01 | 三项优化全部离线、自研、确定性，不引入网络/新数据源/神经模型 | 沿用第一期 NFR/原则 |
| O-02 | 简拼只在输入串可被首字母展开为合法音节切分、且首候选拼首字母无法覆盖时启用；长度 ≥2；与全拼/前缀/缩写路径级联去重 | 防污染全拼主路径 |

### 12.5 功能需求

#### FR-023 简拼/首字母输入

- 输入串为首字母组合（如 `nh`、`wsm`）时，引擎尝试按首字母展开为合法音节切分，并据此查词典产出候选
- 长度 ≥ 2 位才触发；单字母不触发（沿用现有防泛滥策略）
- 与全拼、前缀、缩写路径共存：全拼可完整切分时仍走全拼（简拼只作为补充）；同级候选按"整词 > 整句 beam > 简拼"去重，同文本取最高分
- 验收方向：`nh`→你好、`wsm`→为什么（词典含该词时）；`wo`、`yi` 等可切分全拼不出现简拼噪声；结果确定性
- **开关（T-103，O-05 修订）**：`enable_abbreviation`（默认 `true`）关闭后词典简拼（首字母展开）不介入；联系人索引原生简拼键（FR-037）与网络语缩写路径（FR-016/FR-017）不随本开关变化（边界）

#### FR-024 模糊音与纠错

- 引擎内置模糊音映射，覆盖：`zh/z、ch/c、sh/s、n/l、f/h、an/ang、en/eng、in/ing`（7 组）
- 尾部残缺音节（如 `niha` 的 `ha`）优先尝试模糊补全为完整音节再查前缀补全，使少打字母仍能出候选
- 完整音节打错（如 `fen` 误为 `feng` 反向、`lan` 误为 `nan`）时按映射展开多路候选后统一排序
- 不修改词典数据；映射为解码层行为，结果确定性、可测试
- **开关（T-103，O-05 修订）**：`enable_fuzzy`（默认 `true`）关闭后纠错组（模糊替换 + 少字母补全）整体不生成，其余路径（整句/简拼/前缀）不变
- 验收方向：`niha`→你好；`zongguo`→中国（`z/zh`）；`fag`→发（`f/h`、`an/ang` 纠错）；正常全拼不漂移

#### FR-025 整句/长句输入

- 多音节输入（如 `woxiangmingtianqubeijing`）经 Beam Search 选择全局得分最优的词语组合，不再只取每音节首候选
- 评分复用现有 bigram 与 unigram（整数饱和运算），beam 宽度有上限保证延迟与确定性
- 整词直接命中仍优先（如 `nihao`→你好）；整句 beam 与整词路径合并去重，同文本取最高分
- 单字回退：任一音节查不到词时退化为单字组合，保证至少 1 个候选
- 验收方向：`woxiangmingtianqubeijing`→我想明天去北京；整句候选置于候选列表前部；短串行为不劣化

### 12.6 非功能需求（沿用并与第一期约束对齐）

- 性能：候选刷新延迟 ≤30ms（目标 ≤15ms）门槛不破；整句 beam 宽度受控
- 隐私：仍默认零网络请求（NFR-010）
- 可维护性：算法仍在 `zhu-ye-core`，无 Windows 专有 API
- 确定性：相同输入产生相同候选顺序

### 13.5 功能需求（已定稿）

#### FR-027 数字格式候选

- 拼音为空、无联想（D-05）、连续输入数字串（可含小数点）时，引擎判定格式类型（日期/金额/电话/纯数字）并生成候选格式列表；判定失败返回空（数字直通行为不劣化）
- 输入交互：数字先攒入 digit buffer 并弹空闲候选窗（复用 T-058/059 窗），数字 1-9 上屏对应格式、空格上屏选中行、Esc 关闭；退出（字母/回车）时 buffer 原样补上屏不丢字
- 识别规则（确定性，core 侧）：
  - 8 位纯数字 → 日期：`2026-09-30` / `2026/09/30` / `2026年9月30日` / `2026.09.30`
  - 4/6 位纯数字 → 年份/年月：`2026 年` / `2026-09` / `2026年9月`
  - 含小数点（`\d+\.\d{1,2}`）→ 金额：千分位 `12,345.6`、中文读数 `一万二千三百四十五点六`
  - 11 位 `1[3-9]\d{9}` → 电话：`138 0013 8000` / `138-0013-8000`
  - ≥5 位纯数字 → 千分位 `12,345`；<5 位纯数字不触发（返回空）
- 候选 ≤8 条、确定性排序；来源标注专用类型（数字候选不参与拼音排序）
- 不改**组合态** 1-9 数字键语义（拼音组合时数字键仍选候选）
- 验收方向：`20260930`→4 种日期格式；`12345.6`→千分位 + 中文读数；`13800138000`→电话分段；`2026`→年份；`12`→无候选不劫持；超长串/纯 0 不崩、返回空或最基础格式

#### FR-028 符号快捷 v 模式

- 拼音为空时输入 `v` 开头进入符号分支：`v1`-`v9`→序号组（①⑴⒈…一页）、`vx`→数学符号（±×÷≈≠≤≥∞…）、`vh`→常用标点（，。？！…）
- 与拼音路径隔离：类型码不可切分为拼音（`v` 后接数字/`x`/`h` 均非合法音节开头），天然不污染拼音主路径；`v` 后接其它字符退回正常拼音（如 `vi` 走拼音）
- 冷启动 `v` 单字母：组合为空 + 输入 `v` 时先会话内等待类型码，不进拼音组合
- 候选上屏：数字 1-9 选对应符号、空格选选中行、Esc 关闭
- 符号表内置 core 静态表（每类一页 9 个，初版不贪全）
- 验收方向：`v1`→①⑴⒈ 等 9 个序号；`vx`→±×÷≈≠≤≥ 等；`vh`→常用标点一页；`vi`→不走符号分支；`v` 单独输入无噪声（空或明确提示）

#### FR-029 emoji 推荐

- 内置 emoji 别名表（拼音/中文关键词 → emoji，如 `xiao`→😄、`aixin`→❤️、`ku`→😂），规模 300+（D-04），内嵌 core 静态表（Unicode 标准字符，不引入外部数据源）
- 拼音组合态输入串**整串等于**别名时命中；命中项追加到候选**尾部**，来源标注 Emoji
- 别名命中与普通词并存（`ku`→苦 与 😂 同屏，排序不劣化）；不做前缀模糊（确定性）
- emoji 表按拼音全文字母表排序保证确定性；上屏直接插入 emoji 字符（commit-no-comp）
- 验收方向：`xiao`→候选尾含 😄；`aixin`→❤️；`ku`→苦 与 😂 并存；`xyzabc`→无 emoji；表 ≤512 条、查表 O(1) 不劣化性能门槛

### 13.6 非功能需求（沿用既有约束对齐）

- 性能：候选刷新延迟 ≤30ms（目标 ≤15ms）门槛不破；数字/符号判定为 O(输入串长) 级别，
  emoji 查表为 O(1)（≤512 条静态哈希）
- 隐私：仍默认零网络请求（NFR-010）

## 15. 场景8 领域自动

### 15.1 背景与动机

体验优化文档场景 8（docs/输入法体验优化.md §8）：医疗、法律、金融、代码、人名、地名等
**专业/垂直领域**输入时，用户期望**专业术语优先，不总是通用词**；AI 优化方向 = 领域词库 +

现状：FR-015 已交付「分层词典体系 + 领域词典包（it/med）+ 勾选启用」；T-050 既定命題

不参与排序竞争。用户痛点：即使启用了 it 包，输入 `jubu` 时仍是通用词"局部/布局"在前，
`局部(变量)`、`局部(作用域)` 等 IT 术语埋在尾部，命中率与输入效率不理想。

场景8 领域自动的目标：**识别当前输入串所属领域，把该领域的术语候选提前（提权）**，
让"启用领域包"从"词可达"升级为"词可及"。

- 提供独立进程 `zhu-ye-settings.exe`（新 crate `zhu-ye-settings`）：原生 Win32 顶层窗口 +
  GDI 自绘，复用 `candidate_ui` 的主题与度量纯逻辑；不引入任何 GUI 框架依赖
- 单窗口 + 左侧导航三页：工具箱 / 常用设置 / 关于与更新
- **唤起入口四条**：`ITfFnConfigure` 实现（系统"文本服务和输入语言"属性按钮，走注册到
  `ITfInputProcessorProfiles::Register` 的同一 CLSID，无需新增注册表键）；语言栏按钮右键菜单项
  （只创建进程、不访问引擎状态）；安装脚本创建的开始菜单快捷方式；`zhu-ye-cli settings` 转发
- 单实例：重复唤起激活已有窗口。关窗即退出进程，不驻留
- 未实现条目以**占位**呈现：条目可见可点击，点击后在条目下方展开"正在规划中"说明
  （不做灰显禁用、不做模态弹窗）
- 窗口自身跟随系统深浅色；字体用系统默认 UI 字体（候选窗保持宋体，两者不必一致）；
  复用候选窗的 PerMonitorV2 + `BASE_DPI` 缩放机制

#### FR-040 工具箱

- **emoji 面板**：呈现内置 emoji 表（FR-029，381 条），选中即上屏字符
- **符号大全面板**：按分类结构呈现符号，本期接入 core 现有三组（FR-028，27 个字符）；
  符号集扩充为独立任务（D-33）
- **图片表情**：占位（D-34）

#### FR-041 常用设置

- **主题**：提供浅色 / 深色两项并持久化；高对比度由系统接管且不可手选（D-31）
- **英文输入法**：设置"新会话默认中英模式"（中文 / 英文二选一）；属**装配项**，写入配置持久化，
  重启输入法后新会话从所选模式开始。**不展示"当前模式"**——中英模式是每个宿主进程各自的
  IME 实例状态，跨进程没有可供设置窗口读取的单一值（D-32）
- **更多设置**：三个动作入口——打开配置文件、打开数据目录、打开日志目录（D-36）
- **占位条目**：简繁切换、全半角切换、生僻字输入

#### FR-042 词典包管理界面（兑现 FR-015/FR-022）

- 列出各领域包：**名称、简介、词条数、体积、版本、启用开关**
- 名称与简介取自 core 内置静态表；词条数与体积从 `.zyct` 产物读；版本取自本地已安装包清单
  （`packs/installed.json`，见 17.7）（D-37）
- 勾选状态持久化于 `config.json` 的 `enabled_packs`，重启装配生效（沿用 P-12）
- **导入本地 `.zyct`**：校验魔数 `ZYDT`、格式版本、头部布局与内容 SHA-256 后复制进 `packs/`；
  **不验签**，界面必须说明导入包不参与在线更新的签名信任链（D-38）

#### FR-043 输入法管理与修复

- **管理输入法**：展示本输入法注册状态，并提供"打开系统输入法设置"动作（D-39）
- 注册状态判据与 `scripts/ime-identity.ps1` 的 `Test-TsfRegistration` 一致：`LanguageProfile\
  0x00000804\{ProfileGuid}` 存在且 `Enable == 1`；`InProcServer32` 默认值指向存在的 DLL 且
  `ThreadingModel == 'Apartment'`
- **一级修复（无需提权）**：检测各 `.zyct` 的魔数/格式版本/布局/内容 SHA-256、`config.json`
  与 `user_words.json` 的可解析性；修复 = 重建缺失的 `packs` 目录、把损坏文件改名 `.bak` 后重建
- **二级修复（需要提权）**：重注册 TSF 的两棵 HKLM 注册表树（`SOFTWARE\Microsoft\CTF\TIP\{CLSID}`
  与 `SOFTWARE\Classes\CLSID\{CLSID}`，先删后建、幂等）；DLL 路径从当前 `InProcServer32` 读取，
  读不到则取安装目录下最新的 `zhu-ye-ime*.dll`；完成后重启 ctfmon 使新注册生效，重启前必须确认
- **安全边界**（D-41）：先报告、由用户显式触发修复；只改名备份、绝不删除；DLL 文件缺失时只
  报告"请重新安装"，不提供虚假修复
- 权限：日常设置不需管理员，仅二级修复在点击时提权（D-40）

#### FR-044 检查更新界面（兑现 P-02 手动入口）

- 提供"检查更新"按钮与结果展示；联网由 spawn `zhu-ye-updater` 完成，**设置窗口自身不发起
  网络请求**，保持"唯一联网组件"边界（D-44）
- `online_update` 默认关闭（沿用 P-03）；须由用户在窗口内显式开启后才可检查
- 应用更新需二次确认；同页展示版本信息与诊断信息（配置路径、数据目录、日志目录、已装包列表）

#### FR-045 设置窗口的发布与安装

- `install.ps1` 改为从发行包自身取文件（不再依赖源码树），安装 `zhu-ye-settings.exe` 与
  `zhu-ye-updater.exe`
- **预置三个领域包**（`it`/`med`/`slang`，实测合计 2.25 MB）到 `%APPDATA%\ai-zhu-ye-ime\packs\`，
  使 FR-042 可离线验收（D-46）
- 创建开始菜单快捷方式；`package-portable.ps1` 的包结构同步更新

### 17.5 非功能需求（沿用并对齐既有约束）

- **设置状态三分**（本期确立的术语，见 [CONTEXT.md](../CONTEXT.md)）：
  **运行时开关** = 立即生效并持久化；**装配项** = 写入配置、由消费组件在其下次启动或下次装配时
  读取生效（沿用 P-12 的不热切换口径，如新会话默认中英模式、候选窗主题）；**会话状态** = 立即
  生效但不跨会话保留（如某次输入会话中的组合内容；运行中经 Shift 切换的中英模式亦是会话状态，
  但它不是设置窗口的条目——设置窗口只表达装配项），**中英模式的运行时切换不在窗口内暴露**
- 保存时机：运行时开关即时写入 `config.json`（复用 `save_config` 的原子写）；装配项由用户显式
  "保存"统一提交
- 隐私与网络：`online_update` 默认关闭时设置窗口零网络请求；窗口自身不联网（沿用 FR-012、NFR-010）
- 权限：日常设置不需管理员；仅二级修复在点击时提权
- 可测试性：配置读写、注册状态判据、修复决策、主题解析等纯逻辑必须可在无 GUI 环境单测；
  窗口渲染以 BMP 截图取证（沿用 `candidate-demo --shot` 先例）
- 后台驻留：设置窗口关窗即退出，后台驻留进程数保持 0（NFR-001）
- 可维护性：Rust 侧 TSF 标识常量与 `scripts/ime-identity.ps1` 双份维护，必须有交叉一致性测试（D-42）

### 17.7 新增磁盘格式：已安装包清单

`%APPDATA%\ai-zhu-ye-ime\packs\installed.json`，承载**机器事实**（磁盘上实际存在什么、什么版本），
与承载**用户意图**的 `config.json`（启用哪些包、是否联网）职责分离。

- 字段：每个包的 id、version、内容 SHA-256、安装或导入时间、来源标记（在线更新 / 本地导入）
- 写入方：在线更新器（应用更新成功后）与设置窗口（导入本地 `.zyct` 成功后）
- 版本号独立于 `config.json` 的格式版本；版本高于当前支持时按"未知元数据"处理并降级显示，
  不得因此让设置窗口不可用
- 已安装包清单缺失或损坏时，设置窗口仍须列出 `packs/` 目录中实际存在的包（词条数与体积可从
  产物读），仅"版本"一栏显示为未知

### 21.1 背景与动机

1. **exe 安装包缺失（D-69 兑现）**：官网下载页只有"便携 zip（内测期产物）"，exe 安装包
   标注"规划中"（`site/download/index.html`）。普通用户安装入口为管理员 PowerShell 运行
   `install.ps1`，门槛高、无图形化体验、无卸载入口（虽有 uninstall 脚本但非产品化）。
2. **更新源从未真正可用（重大缺陷实证，T-096 调研）**：客户端更新器默认 URL
   写死 `https://github.com/menghun3-cn/zhu-ye-ime/releases/latest/download/manifest.json`
   （`crates/zhu-ye-updater/src/main.rs:30-31`）。实证其**当前 302 → 404**：
   - 根因：GitHub `releases/latest` 只指向最新**非 prerelease** release；
   - CI 发布（`release.yml`）对含 `-` 的版本自动加 `--prerelease`，GitHub 拒绝将其设为
     latest（显式 `--latest` 亦无效）；
   - latest 因此停留在 v0.1.1-alpha（当年手工发布未标 prerelease，资产只有 zip、**无
     manifest.json**）；v0.1.2-alpha 六项资产齐备（zip/三领域包/manifest/SHA256SUMS）但
     非 latest → 更新器永远取不到 manifest。
   - 推论：**只要保持 `-alpha`（prerelease）发布节奏，GitHub latest 语义下更新源永远
     404**，直到出现非 prerelease 正式版。需用不受 latest 语义影响的**稳定 URL**修复，
     即镜像（P-01 备注"镜像配置留待后续"正好兑现）。
3. **Pages 从未部署成功**：`pages.yml` 已就绪、仓库 Pages 配置为 workflow 模式
   （build_type=workflow），但从未有成功部署（status=null）；官网目前只在本仓库可浏览。

### 21.5 功能需求（草稿-待确认）

#### FR-061 Windows exe 安装包

- **形态**：单文件 x64 exe（Inno Setup [Setup] 节编译），产物小、无运行时依赖分发问题；
  安装时请求管理员权限（`PrivilegesRequired=admin`，UAC manifest）
- **安装行为（复用 install.ps1 语义，差异最小化）**：
  - 从内置载荷释放 `bin/`（zhu_ye_ime-<sha8>.dll + settings/updater exe + en.zyen + base.zyct
    等只读资产）与 `scripts/`（ime-identity.ps1 等）到 `Program Files\ai-zhu-ye-ime\`
  - **版本化 DLL 部署 + PE 导出校验 + 失败回滚**（T-026 语义原样）
  - **HKLM TSF 注册 + 校验 + 回滚**（New-TsfRegistration/Test-TsfRegistration 语义原样）
  - **预置三领域包** it/med/slang.zyct 到 `%APPDATA%\ai-zhu-ye-ime\packs\`（幂等）
  - 开始菜单快捷方式、旧版 DLL 延迟清理（Add-TsfDelayedCleanup）
  - 安装完成页显示"安装完成"并提示开始使用
- **版本检测与覆盖安装**：读取已安装版本（注册表/文件版本），同版本覆盖重装安全
  （幂等：TSF 注册先测后写）；不触碰 `%APPDATA%` 用户数据（配置/用户词/通讯录）
- **卸载**：Inno 卸载器 + 复用 uninstall 语义（Remove-TsfRegistration、DLL/目录清理、
  Program Files 残留清理；与 T-010 演练过的回滚口径一致）；卸载不删除 `%APPDATA%` 用户数据
