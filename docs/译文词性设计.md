# 译文完善与词性显示（第十三期 M16）方案设计

> 状态：已定稿（2026-10-06）
> 前置：需求规格说明书 §22（D-79 至 D-82）；数据源候选调研 §1.1
> 关联：T-115（数据源与 v3 格式）、T-116（候选框布局）、T-117（译文精选与 e2e）

## 1. 问题与目标回顾

2026-10-06 用户本机实地验收点名（核心功能级）：

> 常用单个词/组词普遍没有译文；`你好` 译文为未精炼的 `hello; hi`；`是` 无译文 `yes`；候选框需要显示词性（格式：序号 + 中文 + 词性 + 译文，按最长中文对齐）。

实测坐实（临时探针 `zz_probe` 直读 `%APPDATA%\zhu-ye-ime\dictionary.zyct` 2026-10-05 14:44 build）：

- 抽测 14 个高频词（是/什么/今天/吃饭/谢谢/我们/电脑/开始/朋友/人/大/去/上班 等）首候选 **13 个无译文**；
- `你好` 译文 = 未精炼串 `hello; hi`（应为 `hello`）；
- `是`（shi，88 条候选）首候选无译文；
- 词条格式无词性字段，另无独立词性数据。

本设计给出：v3 词典格式、双数据源管线（CC-CEDICT 译文 + jieba 词性）、词性映射与显示布局、验收口径。

## 2. 设计定案摘要

| 项 | 定案 |
| --- | --- |
| 词典格式 | v2 → **v3**：词条记录 24B → 32B，新增 `pos_offset u32 + pos_len u16 + 2B padding`；文本池同存词性与译文；loader 版本分支（v2 文件 pos 恒空，向后兼容） |
| 译文源 | **CC-CEDICT**（`cedict_ts.u8`，125,223 行，CC BY-SA 4.0）：义项 `/` 分隔 → 清洗 → 精选 1~3 → 微调表覆盖 |

| join 口径 | 以**既有 28.7 万词条为 base**（主排序源与词频不变），中文词（简体）+ 去调拼音双键 join 补译文/词性；CC-CEDICT/jieba **独有词不扩候选集**（候选集与排序零变化） |
| 候选框 | `序号 + 中文 + (最长中文+2空格对齐) + 词性 + 译文`；无词性留空（D-82）；仅绘制层改动 |

## 3. v3 词典格式设计

### 3.1 词条记录扩展

v2 记录（24B，`crates/zhu-ye-core/src/dict_builder.rs` L102-110）：

```
[0..4]  word_offset       u32
[4..8]  pinyin_offset     u32
[8..12] translation_offset u32
[12..16] frequency        u32
[16..18] word_len         u16
[18..20] pinyin_len       u16
[20..22] translation_len  u16
[22..24] padding
```

v3 记录（32B，仅尾部扩展）：

```
[24..28] pos_offset       u32   ; 词性文本在文本池偏移；0 = 无词性
[28..30] pos_len          u16   ; 词性字节长度（UTF-8）
[30..32] padding
```

变更点（`dict_format.rs`）：

- `DICT_VERSION: u32 = 3`
- `ENTRY_RECORD_SIZE: usize = 32`
- 文档注释补「v3 在 v2 布局基础上尾部追加词性字段（固定 8 字节），v2 文件 24B 记录可被 v3 加载器兼容读取（词性恒空）」

### 3.2 加载（`dict_loader.rs`）

- `DictHeader.version` 读取后分支：`version == 3` → 词条视图按 32B 步进取词性；`version == 2` → 24B 步进、`pos_offset/pos_len = 0`（`DictionaryEntry.pos` 恒 `None`）
- 词性读出：`pos_len == 0` → `None`；否则 `text_unchecked(pos_offset, pos_len)`
- `DictionaryEntry` 新增字段 `pos: Option<String>`（core 类型；`candidate.rs` `Candidate` 同步加 `pos`？——见 §5，**不加入 Candidate**，布局层单独从词条取）

> 设计决策（§3.3/§5 详述）：`Candidate` 模型**不加**词性字段；候选窗按**词条查找**词性（`entry.pos`）——理由：词性只影响首栏渲染，不参与排序/翻页/上屏；保持候选管线零耦合。

### 3.3 索引表

- 中文词→译文索引（`translation_by_word`）不变（译文内容=精选版）
- 英文反查索引不变
- **不新增中文词→词性索引**：词性随词条记录读取即可（候选来自词条）

## 4. 数据管线（T-115）

### 4.1 输入与格式

- **CC-CEDICT**：`cedict_ts.u8`，行：`傳統 簡體 [拼音] /义项1/义项2/.../`（义项间 `/`；义项内部 `;` 为细分不拆）。实际样例：

  ```
  是 是 [shi4] /to be (followed by substantives only)/correct; right; true/(respectful acknowledgement of a command) very well/(adverb for emphatic assertion)/
  你好 你好 [ni3 hao3] /hello; hi/
  今天 今天 [jin1 tian1] /today/the present time; now/
  ```

  解析：取简体（第 2 字段）与去调拼音（`[a-zA-Z ]+` 剔除数字与 5/ü→v 归一，与既有词库拼音体系对齐）；义项 = `/` 切分后清洗（去空白）；**首批 60 行实测含 5 个 `#` 头注释行，全部跳过**。

- **jieba**：`dict.txt`，行：`词 词频 词性`（如 `是 85462 v`、`你好 1200 nr`？——jieba 对"你好"标注 `nr`？jieba 实际（人名误标）——按数据结果为准）。取中文词 + 词性标签。

### 4.2 join 与构建

1. 既有词库条目（词、拼音、频）→ `HashMap<(词, 去调拼音), 序号>`
2. CC-CEDICT 解析结果逐条按（简体词, 去调拼音）命中 → 写译文（精选，§4.3）
3. jieba 逐词按（词）命中（拼音同键 join：jieba 无拼音 → 以既有条目的拼音为准；一个词多音时**首个拼音条目**取词性，其余条目留空——多音词词性在首读音上）→ 写词性（映射，§4.4）
4. 微调表覆盖（`data/translations-overrides.txt`，§4.5）→ 重新写译文
5. 重建词典（`zhu-ye-dict` builder 保持输入数据源结构；新增可选 v3 字段输入）

> 数据源文件不进 git（AGENTS §5 禁大文件/原始数据）；管线脚本接受数据路径参数（样例：`%TEMP%\cedict_ts.u8`、`data/external/jieba-dict.txt` 经 `.gitignore` 排除）。构建命令入口沿用 FR-019 一键构建脚本扩展。

### 4.3 译文精选算法（T-117 语义，T-115 落地）

```
select_translations(def_terms, overrides):
  terms = def_terms.map(清洗)          # 去括号注、去 (coll.)/(slang)/等、去空白、去尾 "。" 类
  terms = terms.filter(非空)
  if 微调表命中(词): return overrides[词]         # 1~3 义项，分号分隔
  picked = terms[0..min(2, len)]        # 默认取前 2 义项
  if len(terms) >= 2 and 义项1 为纯括号标注（"abbr. for ..." 等元描述）: picked = terms[1..3]
  return picked.join("; ")
```

- 「是」→ 微调表 `yes; be`（用户点名；源义项 `to be (followed by substantives only)/correct; right; true/...` 首义为系动词，精选会得 `to be; correct`，不满足用户对 yes 的期望 → 覆盖）
- 「你好」→ 微调表 `hello`（源义项 `hello; hi` 单义项含细分 → 取 hello）
- 其余词条默认规则收敛译文长度：每条义项 ≤ 40 字符截断防候选窗爆宽

### 4.4 词性映射表（jieba ICTCLAS → 用户缩写）

用户缩写表（D-81）：n. pron. v. adj. adv. num. art. prep. conj. interj. det. aux. modal part. ger. inf. ppl.

| jieba 标签 | 含义 | 映射 | 备注 |
| --- | --- | --- | --- |
| n / nr / ns / nt / nz / ng / an / vn | 名词/人名/地名/机构/专名/名语素/名形词/名动词 | **n.** | 实质名词统一 |
| v / vd / vg | 动词/副动词/动语素 | **v.** | 「是」→ v.（实测 jieba `是` 标签 v） |
| a / ad / ag | 形容词/副形词/形语素 | **adj.** | |
| d | 副词 | **adv.** | |
| r | 代词 | **pron.** | |
| m | 数词 | **num.** | |
| q | 量词 | **num.** | 近似归数词类（用户表无量词位；设计注明） |
| p | 介词 | **prep.** | |
| c | 连词 | **conj.** | |
| e | 叹词 | **interj.** | |
| y | 语气词 | **part.** | 「吗/呢」类语气助词≈小品词 |

## 5. 候选框布局（T-116）

### 5.1 呈现格式（用户指定）

```
1 通货膨胀  n.  inflation
2 今天      n.  today
3 你好      v.   hello      ← 无词性则为空：`3 你好        hello`
```

- 序号（既有 1-9 键位序号）与中文之间 **1 个空格**
- 词性列起始 X = 序号列宽 + 1 + **本页/本窗最长中文词汇宽度 + 2 空格**（用户指定："以候选框上最长的中文词汇之后的两个空格为对齐"）
- 词性与译文之间 **1 个空格**；译文沿用弱化样式（FR-005 灰阶），词性可用英文色（与译文同弱化级或略强，主题可调）
- 无词性词条：对齐列后直接译文（词性列空）

### 5.2 绘制层改动（`candidate_window.rs` / 现有 GDI 行绘制）

- 行内三/四段 x 偏移计算：序号段（现有）→ 中文段（现有居中/左对齐基线不变）→ 词性段（x = 中文段后 + 对齐空隙）→ 译文段
- 对齐基准：候选页内最长中文（`max_text_width` 现成语义；用 `GetTextExtentPoint32W` 或现有测宽函数）
- 空词性：词性段零宽，译文段直接左移
- 数据来源：候选来自词条时读出 `entry.pos`；`Candidate` 不新增字段（§3.2 决策）——实现时若现候选管线无法回溯词条（如用户词/领域包候选），则**词性显示仅对词条来源候选生效**，其余候选无词性（标注在验收口径）

- 扩充 `candidate-demo` 演示视图：注入带词性样例（`是 v. yes; be`、`今天 n. today`、`通货膨胀 n. inflation`、无词性样例）三种宽度差异
