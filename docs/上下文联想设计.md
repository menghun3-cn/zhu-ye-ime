# 上下文联想补全设计（T-058/T-059，场景 5）

> 分类：设计 ｜ 状态：T-058 检索层已完成 / T-059 引擎承接 ｜ 关联任务：T-058、T-059

## 1. 需求（场景 5 原文与用户确认口径）

体验优化文档场景 5：*输入"今天天气"后，候选"怎么样 / 不错 / 很好"——结合前文，而不是孤立看拼音*。

用户 2026-09-30 确认三项口径：
1. **触发时机**：上屏后空闲候选窗——输入法按空格/数字上屏当前词、拼音为空时，候选窗直接给出前文的高频后继词，可数字键直接上屏；
2. **联想来源**：词典 bigram 后继检索（新增"前词→后继"检索能力，兼容可回退）；
3. **范围**：Top5 整词 + 短短语（两词短语，如"明天见→明天见你"）。

## 2. 数据侧事实（决定零格式改动）

- v2 词典 bigram 表按 `(previous, word, frequency)` 三键排序构建（`dict_builder`），
  合并去重后**相同前词的记录在表中连续**。
- 现有 `frequency(prev, word)` 是全局二分点查；"前词→后继列表" = 对 `(previous, "")`
  二分取**下界**，顺序扫描连续区段直到前词变化，按频率降序截取 TOP N。
- 因此**无需改字节格式**，只需 loader 侧新增检索读取。

## 3. T-058 检索层（已完成，本设计第一版落地）

- `BigramModel::successors(previous, limit) -> Vec<(String, u64)>`：
  trait 默认空实现（未提供后继索引的模型退化为不联想，不影响现有排序语义）；
  `InMemoryBigramModel` 按频率降序、同频词形字典序；`EmptyBigramModel` 空；
  `DictionaryFile` 下界二分 + 区段扫描 + 区段内按频率取 TOP；`CompositeDictionary`
  各源取后继后按词合并 **max**（与 `frequency` 同口径）再截取。
- `suggestion_candidates(model, previous) -> Vec<String>`：Top5 整词 + 至多 3 条
  **"前词+后继"** 两词短语（明天见→明天见你；后继与前词同形跳过），总量 ≤8，
  短语置整词之后；`previous` 为空返回空（联想只在"刚上屏过一个词"后触发）。
- CLI 抓手：`zhu-ye-cli suggest <词典> <前词>`（与引擎同口径，供调试与 VM 验证）。

### 3.1 口语联想覆盖表（T-105，2026-10-05 修订，T-058 数据项）

bigram 语料为 OPUS GlobalVoices 新闻语体，"怎么样/不错"等口语后继不在高频区。
按用户点名清单（"口语语料替换 T-058 数据项"）新增 **core 静态口语覆盖表**
（`crates/zhu-ye-core/src/spoken.rs`，`SPOKEN_SUGGESTIONS`：31 个高频日常前词 →
口语后继整词，≤5 条/词）：

- **命中**：`suggestion_candidates` 整词区完全采用口语列表（替换新闻语体后继），
  短语区仍由 bigram 补充（"今天早上/今天天气"式短语保持有用），总量 ≤8 不变；
- **未命中**：整词区维持 bigram 统计原逻辑（语体、排序行为零变化）；
- **边界**：前词整词匹配（不做分词）；`previous` 空返回空；T-057 基准不回退
  （联想只出现在上屏后空闲窗，不参与拼音候选排序——机制层零改动，仅数据层替换）；
- **数据合规**：人工维护的中性日常口语词（无第三方内容、无许可义务，同简拼/
  模糊音音频表口径）；选词原则"中性/常用/无敏感"，规模与格式由测试强制。

## 4. T-059 引擎承接（下一阶段）

- 引擎状态机：composition 由非空→空（上屏完成）时记录刚上屏词为 `last_committed`；
  拼音仍为空且 `last_committed` 非空时，空闲候选窗显示 `suggestion_candidates`；

  联想态回主输入路径；Backspace/清屏不触发；重叠词处理与 UI 标注按 M7 既有模式；
- host-e2e `--m8` 断言组 + VM 交互验收（验收标准 8.1 同款）。
