# 产品化日志目录设计（FR-060，T-091）

> 分类：设计 ｜ 状态：需求已定稿（D-72/D-73 用户确认）、方案定稿 ｜ 关联任务：T-091
> 需求来源：[需求规格说明书 §20](<需求规格说明书.md#20-候选覆盖增强与诊断产品化>)（第十一期，FR-060）。

## 1. 需求与已确认口径

背景缺口（T-075 ⑤）：

- TSF 侧文件日志写死在 `C:\zhu-ye-test\tsf-debug.log`、仅当 `C:\zhu-ye-test\tsf-debug.enable`
  哨兵存在时启用（`tsf.rs` 的 `FILE_LOG_PATH`/`file_log_enabled`）——**验收期设施，非
  产品日志**：位置不在用户目录（不满足验收标准 FR-012"本地日志仅写入本地用户目录"）、
  无级别、无大小控制、注释明言"验收结束后移除"；
- 设置窗口更多设置"日志目录"（D-36）与关于页诊断信息在生产环境因此没有对应物，文案
  只能如实写"文件日志仅在验收期启用"。

| 项 | 确认结果 |
| --- | --- |
| D-72 默认级别 | warn——只记错误级，热路径零文件写、不打扰正常使用；需要时手动调 info/debug |
| D-73 VM 验收兼容 | 哨兵双轨保留——产品模式写 `%LOCALAPPDATA%` 日志目录；`C:\zhu-ye-test` 哨兵存在时仍写原路径全量（vm-accept-sop 零改动） |

## 2. 总体架构

日志设施分三层，全部"尽力而为、零失败影响"：

```
core（zhu-ye-core，纯 std，零 Windows 专有 API）
  ├─ log_level.rs   LogLevel 枚举（error/warn/info/debug + serde 宽松解析）
  └─ file_log.rs    FileLogger：目录准备 / 级别门 / 追加写 / 1 MiB 轮转（纯 PathBuf 输入）
                        ↑ 目录由调用方解析（%LOCALAPPDATA% 读取在各消费方）
                        │
ime（zhu-ye-ime/tsf.rs）      settings（zhu-ye-settings）
  ├─ 解析 %LOCALAPPDATA% 与 config.log_level     ├─ 更多设置"日志目录"指向产品目录
  ├─ 将现 debug_log 全调用点分级                   └─ 关于页诊断信息文案更新
  └─ 哨兵存在 → 全量写 C:\zhu-ye-test（现状零改动）
```

- **core 零 Windows 依赖**（AGENTS §4 / 架构约束）：`FileLogger` 只拿 `PathBuf`；
  `%LOCALAPPDATA%` 的读取（`std::env::var_os("LOCALAPPDATA")` 属标准库、非专有 API）
  放在消费方（ime 装配 / settings `product_log_dir()`），与既有 `APPDATA` 数据目录
  （`settings::config::data_dir`）同一模式；
- **config 字段**：`ConfigFile` 新增 `log_level: LogLevel`——serde 默认 `warn`、
  `deserialize_with` 宽松解析（缺失/非法/未知值回退 warn 且不动其它字段、不递增
  `CONFIG_FORMAT_VERSION`），与 `theme`/`default_mode` 的宽松模式一致（T-073 教训）；
- **热路径零抢占**（AGENTS §4）：级别门在**消息构造前**短路——debug 级调用点默认
  warn 下不构造字符串、不查哨兵路径以外的状态（哨兵存在性检查仅首次缓存
  `FILE_LOG_CHECKED`，现状机制保留）。

## 3. core `file_log.rs`（纯 std）

```rust
pub enum LogLevel { Error, Warn, Info, Debug }   // 序：Debug > Info > Warn > Error

pub struct FileLogger {
    level: LogLevel,             // 产品模式当前级别（config 解析结果）
    path: PathBuf,               // 产品日志 ime.log
    size_limit: u64,             // 1 MiB；0 = 不限（测试注入）
}
impl FileLogger {
    pub fn new(path: PathBuf, level: LogLevel) -> Self;
    /// 确保父目录存在（create_dir_all）；失败静默返回 Err，调用方忽略。
    pub fn ensure_dir(&self) -> std::io::Result<()>;
    /// 级别门 + 追加写（append/create）；行长超限时先轮转（当前文件 > size_limit
    /// → 复制为 .1.log 覆盖旧档，再写新文件）。全部尽力而为。
    pub fn write(&mut self, level: LogLevel, line: &str);
    /// 行格式：[unix秒] pid=N tid=N <LEVEL> message
    pub fn format_line(level: LogLevel, message: &str) -> String;
}
```

- 轮转策略：单文件 `ime.log`，超过 1 MiB 时先写 `ime.1.log`（覆盖），再开新 `ime.log`
  ——实现为"写前长度检查 + 重命名/覆盖"，与 `installed.json` 的原子写不同：日志轮转
  允许丢最后一条（尽力而为，不引入临时文件与 rename 复杂度）；
- 无内部锁：TSF 侧在单线程消息循环内调用，不需要 `Mutex`；多进程不共用（ime 进程
  与 settings/updater 各有各的进程，settings/updater 本期不写文件日志）；
- 单测注入临时目录 + 小 `size_limit` 验证轮转边界。

## 4. ime 侧改造（`zhu-ye-ime/src/tsf.rs`）

### 4.1 调用点分级（现有 `debug_log` 全量归类）

| 级别 | 调用点（现状编号） | 内容 |
| --- | --- | --- |
| error | Activate keystroke-mgr FAILED、key-sink FAILED、langbar skip、config-warn、pack-skipped、dict-fallback、配置回退 | 失败/降级类 |
| warn | config-unknown-pack、config-missing-pack、vcf 缺失/不可读、slang-open-failed、候选加载校验回退 | 可恢复异常 |
| info | Activate/Deactivate/OnSetFocus/ActivateEx、langbar added/removed、pack-ok、composite-ok | 生命周期/装配 |
| debug | 其余（key、cand-hide/show、comp-*、commit、v-consume、replace-last、枚举键） | 键击/候选流 |

消息前缀 `zhu-ye: ` 保留（既有排查 grep 习惯、VM 取证断言 `zhu-ye: Activate` 等依赖）。

### 4.2 双轨写策略（D-73）

```
file_log_enabled()（哨兵存在，首次缓存）
├─ true  → 现状全量写 C:\zhu-ye-test\tsf-debug.log（消息无级别过滤、格式不变）——VM 零改动
└─ false → 产品写：级别门（config.log_level 默认 warn）→ FileLogger 写
            %LOCALAPPDATA%\zhu-ye-ime\logs\ime.log（construct 前短路）
```

- 哨兵检查保留（`FILE_LOG_ENABLED`/`FILE_LOG_CHECKED` 缓存）；
- 产品目录与级别在**首次真正需要写时**解析（惰性，每次消息构造后才有路径解析成本；
  默认 warn 下 error/warn 调用点稀少，成本可忽略）；`ensure_dir` 每次写前幂等调用
  （`create_dir_all` 对已存在目录无操作，成本 µs 级且仅在达到级别的消息上发生）；
- `debug_log(message)` 签名保持（避免改动 30+ 调用点），新增内部
  `product_log(level, message)`：哨兵模式全量写，否则按级别门；`debug_log` = 现有
  全部调用点映射为对应级别后调用 `product_log`。

### 4.3 OutputDebugStringW

保留（现状行为，调试器可见、release 空转无成本）。

## 5. settings 侧联动

- `config.rs`：`acceptance_log_dir()` 移除/改名——新 `pub fn product_log_dir() -> Option<PathBuf>`
  = `%LOCALAPPDATA%` + `zhu-ye-ime\logs`（与 `data_dir()` 同模式）；
- `window.rs` 更多设置"日志目录"（D-36 条目）：打开目标改为产品目录；产品目录在
  ime 首次写日志时已创建，但设置窗口独立进程可能先打开 → `ensure_dir` 幂等创建后才
  `ShellExecuteW`（**先判断/创建再打开**，T-075 ⑤ 既有原则）；条目说明文案由
  "文件日志仅在验收期启用"改为"产品日志目录（默认记录错误，级别见 config.json log_level）"；
- 关于页诊断信息（FR-044 / T-077 诊断子视图）："日志目录"行指向产品目录并注明
  默认级别；`model.rs` 对应说明文案同步（`LogDir` 条目 L119）；
- 配置文件 `config.json` 首次写入 `log_level`：settings 不必主动写默认值（不存在的
  字段按默认 warn 处理，serde default），避免无意义写盘。

## 6. 确定性 / 测试策略

- **core**：`LogLevel` 解析（合法值/大小写/非法/空 → 回退 warn）；`FileLogger`——
  追加写、ensure_dir 创建、级别门（低于 level 的 write 不碰文件）、轮转（size_limit
  注入：写满 → 下一次 write 触发 .1.log 覆盖）、行格式（时间戳前缀存在、内容含级别）。
- **ime**：`product_log` 双轨（哨兵 = 全量写旧路径；无哨兵 = 级别门写临时 %LOCALAPPDATA%）
  ——单元级通过注入临时路径；`config.log_level` 解析联动。
- **settings**：`product_log_dir()` 路径拼接；说明文案断言；`--shot` 取证复用。
- **host-e2e**：不直接依赖日志文件（日志非输入功能）；既有 `--m*` 断言组全量回归。
- **验收标准 FR-012"本地日志仅写入本地用户目录"**：产品模式断言日志落
  `%LOCALAPPDATA%\zhu-ye-ime\logs\`（测试注入环境变量）。

## 8. 风险与备选

- **现有讯息格式/路径改变破坏排障习惯**：双轨保留 `zhu-ye:` 前缀与哨兵全量写，既有
  grep 断言兼容；产品日志行格式带时间戳增强可读性。
- **`%LOCALAPPDATA%` 缺失**：回退不写文件（尽力而为），不影响输入；判空后跳过
  FileLogger，`debug_log` 仅保留 OutputDebugStringW。
- **单文件 1 MiB 轮转丢尾部**：接受（日志丢失不影响功能；未来如需升级为多代轮转再
  加 index 序号）。
- **updater/settings 进程不写文件日志**：本期范围界定（CLI/updater stderr 已有诊断），
  e2e 与验收证据均来自 TSF 产品日志；如后续需要，复用同一 `FileLogger` 即可。
