## 3. 总体架构

三个新能力全部落在 `zhu-ye-core`（纯算法），TSF 层只做键路分发与文档编辑，延续既有职责划分：

- **英文候选组（D-10）**：挂接 FR-017 的"非拼音字母串"判定之后——输入串整体无法拼音切分时，
  先查英文词表前缀；命中 → 出英文候选组（置主候选之后）；未命中 → 走既有缩写/网络组。
  拼音能完整切分（如 `nihao`）时英文组完全不介入，中文命中优先；
- **邮箱/网址（D-11）**：组合态捕获 `@` 与 `www.`/`http` 前缀 → 引擎进入 EMAIL/URL 识别分支，
  候选走既有候选窗（组合态窗，非空闲窗）；
- **数据**：英文词表 = core 静态表（内嵌，不改 v2 词典二进制格式）+ CEDICT 英文侧构建期
  提取合并；来源与许可记录进 docs/licenses.md（NFR-008）。

### 3.1 为什么英文词表内嵌 core 静态表（而不是改 v2 词典格式）

- 10k 自建 + CEDICT 英文侧（~1-2 万干净词目）≈ 15-30k 条 × ~16B ≈ 240-480KB 二进制增量
  （release DLL 805KB → ~1.1-1.3MB），体积可控；查键为小写 ASCII 归一化，静态表可二分
  前缀扫描（同 bigram 区段扫描模式），零解析、零 mmap 依赖；
- 改 v2 格式需动 dict_header/版本/构建链并触发全量回归 + NFR-007 可复现重验证，收益不达
  成本；英文词表频率远低于中文词频变化节奏，随发版内置足够（14.3 非目标：替换走词典包渠道
  的措辞改为"词表随发版维护"）；
- 静态表与 emoji 表（FR-029）同为"数据即代码"，构建管线复用既有 import/打包脚本思路，
  生成 `.rs` 表文件入库（源码可审、diff 可见）。

## 4. FR-030 英文拼写候选

### 4.1 词表数据

`EnWordEntry { word: &'static str, freq_rank: u16 }`（实测以构建期生成；freq_rank 越小越常用，
仅组内排序用，不进入中文静态排序）：

- **10000 词档（D-12，T-064 实现口径）**：以 FrequencyWords 英文词频（D-018，CC BY-SA 4.0，
  与既有 D-004 同 repo 同许可）前 10000 为基座，规则清洗（去重、小写归一化查键、长度 ≥2 ≤32、
  ASCII a-z/a-z' 字符集），**人工大小写补丁表**（D-019，data/patches/en-capitals.tsv，随版本维护）
  标注原形大小写（`iPhone`/`API`/`QQ` 等；命令/小写两可词如 `python`/`java`/`git` 保留小写原形），
  补丁可强推低频专名进入与调整组内排序；来源与许可证记录（docs/licenses.md）；
- **CEDICT 英文侧（D-08）**：构建期从 CEDICT 译文字段提取**纯单词/纯字母词目**（过滤
  `(informal)` 括号注释、含空格的多词短语、非 ASCII），与小写归一化键去重合并；来源与许可证
  记录（CC BY-SA 4.0，见 docs/licenses.md）；
- 合并后查键表按 norm 字节序升序、静态表二分 + 前缀区段扫描；同 norm 多词按 freq_rank 排序
  稳定输出。

### 4.2 触发与判别（core 侧，确定性）

1. 拼音切分（既有 syllable DP）整体失败（或剩余不可切分片段）→ 字母串路径；
2. 字母串路径内：全小写化后对英文词表做**前缀匹配**；命中 ≥1 → 英文候选组；
3. 未命中 → 原样回落既有 FR-017 缩写/网络组（`yyds` 等行为不回退）；
4. 长度 <2、含数字/其它字符（非 a-z'）不触发英文组（缩写路径既有门槛保持）；
5. 组合态可切分（`me`、`api`）时英文组不介入（中文候选优先，D-10）。

### 4.3 大小写（D-09）

- 查键 = 输入串小写化（ASCII）；候选 = 词表原形（`pytho`/`PYTHO` 均出 `python`；
  `iphon`/`IPHON` 均出 `iPhone`；`ap`/`AP` 出 `API`/`Apple` 依词表与频级）；
- 不做大小写猜测/转换（非目标）；词表里 `iPhone` 与 `iphone` 若都存在，用频级区分。

### 4.4 候选展示与上屏

- 英文候选行主文本 = 英文原形；有 CEDICT 释义词的右侧弱化展示中文释义（复用既有行内
  译文渲染与 `CandidateUiItem.translation`，FR-032 衔接）；
- 来源标注 `EnWord`（UI 不新增标签样式，沿用缩写组外形语义）；
- 上屏：数字/空格/回车选词 → 上屏英文原形，清组合；
- 英文态下 Esc 清空、字母继续追加（前缀重匹配）、退格回退、输入变回可切分拼音串时
  英文组自动退出（回到拼音路径）。

### 4.5 与 T-057 基准的关系

英文候选只出现在"拼音整体切分失败"的字母串路径（评测集全部为合法拼音串，
`data/eval/words-top2000.tsv` / `sentences-100.tsv` 无英文词）→ 中文候选与排序路径零触碰，
T-057 复跑应逐位一致（验收以复跑数据为准，同 T-061 流程）。

## 5. FR-031 邮箱/网址格式候选

### 5.1 TSF 键路扩展（D-11）

- 新增 `KeyAction::At`：`VK_SHIFT`+`2`（shift 态字母键路径之前拦截，产出 `@`）——仅当
  引擎处于组合态/字母串态；空闲态 `@` 放行宿主（同数字 `.` 键策略）；
- 组合态内的 `.` 键已由数字模式独占判断，邮箱态时同样进入组合串（`.` 是 VK_OEM_PERIOD，
  需在 email/url 态重定向）；`/`（VK_OEM_2）与 `:`（VK_OEM_1）在 url 态进入组合串；
- 引擎尾部追加语义：组合串含 `@` → EMAIL 分支；以 `www.`/`http://`/`https://` 开头 → URL 分支。

### 5.2 识别规则（core，确定性）

| 输入形态 | 类型 | 候选 |
| --- | --- | --- |
| 组合串含 `@`，local 部分 `[a-z0-9._%+-]+` | EMAIL | 前缀补全：`me@163` → `me@163.com` / `me@163.cn` / `me@163.net`（至多 3 条） |
| 组合串以 `www.` 开头且域名前缀 `[a-z0-9-]+` | URL | `www.example` → `www.example.com` / `.cn` / `.org` |
| 组合串以 `http://` / `https://` 开头 | URL | 直通 + 补全（无 `www.` 给 `http://example.com` 形态） |
| 其它 | — | 不触发，候选窗不弹 |

- 已含完整域名（`.com` 结尾等）时直通，不重复补全；字母键继续输入则随时重新判定；
- 邮箱/网址候选**未选中时**：Esc 清分支回拼音组合（保留已输入串），退格删除尾部，字母继续
  输入（如 `me@163.com.cn`）。

### 5.3 交互（复用 FR-027 基底，但无替换链）

与数字格式不同，邮箱/网址是**组合态**输入：选中候选时直接上屏全文并清组合（commit-full，
无"正文里先出现半截"的视觉问题，不需要 replace_last_chars；输入过程中的字母串本身不直接
上屏，保持组合态既有语义）。数字 1-9 选对应候选、空格选选中行、Esc 退出到拼音组合。

## 8. 风险与备选

- **英文触发误判**：英文字母串路径侵入缩写/网络组 → 用"英文词表前缀命中才出英文组"
  强门槛隔离；缩写行为以既有断言锁死（host-e2e m6/m7 缩写用例）。
- **词表质量**：自建 10k 混入错拼/大小写不一致 → 种子审校 + 规则清洗全表测试（字符集、
  长度、norm 唯一性、freq_rank 有界）。
- **CEDICT 英文侧噪声**（解释短语混入）→ 只提取纯字母词目过滤括号注释；仍然可疑的条目
  由去重 + spot-check 测试拦截；不行则降级为"仅反查补全，不进入上屏候选"（备选 B）。
- **@ 键捕获干扰拼音路径**：`me@`.`com` 等场景 `@` 出现前 `me`/`163` 已是合法组合 → 仅在
  组合串含 `@`/`www.` 前缀后重定向，未出现前一切照旧；`@` 空闲态放行宿主（不吞键）。
- **备选 A（词表走 v2 词典格式扩展）**：不采用（见 3.1），留作词表规模远超 30k 时的演进点。
