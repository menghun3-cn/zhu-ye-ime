# 竹叶输入法 设置窗口设计

## 文档信息

- 版本：v0.1.0
- 状态：已定稿（需求已确认，实现待开工）
- 日期：2026-10-02
- 关联需求：[需求规格说明书.md §17](./需求规格说明书.md)（FR-039 至 FR-045，决策 D-23 至 D-47）
- 关联任务：T-072 至 T-080
- 关联决策记录：[Agent Note](../.agents/notes/proposed/architecture/2026-10-01-settings-window-process-and-registration-ownership.md)

## 1. 设计目标与原则

1. **不引入 GUI 框架**：沿用候选窗已验证的"原生 Win32 顶层窗口 + GDI 双缓冲自绘"路线，
   复用 `candidate_ui` 的主题与度量纯逻辑；不引入 egui/winit/WebView2 等运行时
2. **纯逻辑与 Win32 分离**：配置读写、注册状态判据、修复决策、主题解析、包清单扫描全部做成
   无 Win32 依赖的纯函数，可在无 GUI 环境单测（沿用 `candidate_ui` 的可测性模式）
3. **进程边界清晰**：设置窗口是独立进程，与 TSF DLL 无进程内耦合；DLL 不因设置窗口新增任何
   依赖，热路径不受影响
4. **网络边界不变**：唯一联网组件仍是 `zhu-ye-updater.exe`；设置窗口不发起网络请求
5. **权限最小化**：日常设置不需要管理员；只有二级修复在用户点击时提权，且提权动作走一个受限
   的非交互子命令，不整窗提权

## 2. 总体架构

```text
+---------------------------------------------------------------+
| 宿主应用（记事本/浏览器/IDE…）                                 |
|  +----------------------------------------+                   |
|  | zhu-ye-ime.dll（TSF 文本服务）          |                   |
|  |  tsf / input / candidate_window         |                   |
|  |  lang_bar：OnClick 空、右键菜单项"设置…" |----+              |
|  +----------------------------------------+    |              |
+------------------------------------------------+|--------------+
                                                 | CreateProcess
+------------------------------------------------v--------------+
| zhu-ye-settings.exe（独立进程，本次新增）                       |
|  ui / pages / config / registry / repair / inventory          |
|  updater_bridge -------------------+                          |
+------------------------------------|--------------------------+
                                     | CreateProcess
+------------------------------------v--------------------------+
| zhu-ye-updater.exe（唯一联网组件，既有）                        |
+---------------------------------------------------------------+
```

四条唤起入口（D-26）：

| 入口 | 机制 | 是否需新增注册表键 |
| --- | --- | --- |
| 系统"文本服务和输入语言"属性按钮 | TIP 类对象实现 `ITfFnConfigure`；系统用注册到 `ITfInputProcessorProfiles::Register` 的同一 CLSID 加 `IID_ITfFnConfigure` 取接口 | 否 |
| 语言栏按钮右键菜单 | `ITfLangBarItemButton::InitMenu` 添加菜单项、`OnMenuSelect` 处理；当前两者返回 `E_NOTIMPL` | 否 |
| 开始菜单快捷方式 | 安装脚本创建，直接指向 `zhu-ye-settings.exe` | 否 |
| 命令行 | `zhu-ye-cli settings` 转发（沿用 `dict update` 的进程转发模式） | 否 |

菜单项与 `ITfFnConfigure` 都只创建进程，**不访问引擎状态**，因此不受 [lang_bar.rs](../crates/zhu-ye-ime/src/lang_bar.rs)
已记录的约束（引擎状态为 `Rc<Mutex<_>>` 非 `Send`，ctfmon 回调线程不可安全进入）。

右键菜单项**不采用**语言栏按钮左键单击（D-26 否决）：左键是候选窗之外最显眼的入口，占用它
会堵死"点击切换中英模式"的演进方向。

## 3. 模块设计

```text
zhu-ye-settings
  ├── ui          窗口类注册、消息循环、GDI 双缓冲绘制、DPI、深浅色解析
  ├── pages       三页的视图模型（纯逻辑：条目列表、状态、占位展开态）
  ├── actions     条目动作分发（打开目录/切换会话状态/触发修复/触发检查更新）
  ├── config      配置读写（复用 core pack_config，新增主题字段）
  ├── inventory   packs 目录扫描 + installed.json 读写 + 内置包静态表查询
  ├── registry    TSF 注册状态判据与两棵 HKLM 树的读写
  ├── repair      两级修复的决策与执行（纯决策 + 提权子命令）
  └── updater_bridge  spawn 更新器、解析其输出、回传结果
```

依赖方向：`ui` → `pages`/`actions` → `config`/`inventory`/`repair` → `registry`。
`config`/`inventory`/`repair`（决策部分）不得依赖 Win32，以保持可单测。

### 3.1 窗口

- 单实例：进程启动时创建固定名命名互斥体；已存在时用 `FindWindowW` 找到类名对应的窗口并
  `SetForegroundWindow` 后退出
- 关闭即退出进程，不驻留托盘（D-27）
- 深浅色解析：设置窗口**跟随系统深浅色**（D-30），高对比度时走系统配色。实现只读取系统主题
  设置，**不改动候选窗**——T-030 的"候选窗默认固定浅色、不读系统深浅色"只约束候选窗，两者
  服务不同任务（候选窗需与文档背景融合，设置窗口是常规桌面窗口）
- 字体：系统默认 UI 字体；候选窗保持宋体（T-034），两者不要求一致
- DPI：复用候选窗的 PerMonitorV2 + `BASE_DPI` 缩放口径

### 3.2 占位呈现

未实现条目在 `pages` 视图模型中带"规划中"标记与说明文本；`ui` 将其渲染为可点击条目，
点击后在该条目下方展开说明（D-25）。不采用灰显禁用（用户无法得知将来会做什么），
不采用模态弹窗（四个占位会打断四次）。

## 5. 配置与包清单

### 5.1 `config.json` 的增量

新增主题字段，取值 `light` / `dark`，缺失时按 `light` 处理（与候选窗默认浅色一致）。

两个装配项的消费时机不同，界面文案须区分：**主题**由 TSF DLL 在下次装配时读取，故需重启输入法；
**`online_update`** 由更新器在每次被调用时读取，故保存后下次检查即生效，无需重启输入法。

**不递增 `CONFIG_FORMAT_VERSION`。** 加载器对"版本高于当前支持"的处理是回退默认（仅基础包），
递增会让一次降级安装直接丢掉用户已勾选的 `enabled_packs`；纯增量可选字段在反序列化时天然
向后兼容（旧文件缺字段取默认值），不需要版本门槛来保护。

### 5.2 `installed.json`（新增磁盘格式，见需求 17.7）

```json
{
  "version": 1,
  "packs": [
    { "id": "it", "version": "2026.09.29-p3", "sha256": "…", "installed_at": 1759420800, "source": "update" }
  ]
}
```

- 位置：`%APPDATA%\ai-zhu-ye-ime\packs\installed.json`
- 写入方：在线更新器（应用成功后）与设置窗口（导入本地 `.zyct` 成功后）
- `source` ∈ `update` / `import`；导入的包无签名、可能无版本，版本栏留空并在界面标注"本地导入"
- 清单缺失或损坏时降级：仍列出 `packs/` 中实际存在的 `.zyct`（词条数与体积从产物读），
  仅版本栏显示未知；**清单问题不得让设置窗口不可用**

并发写：`config.json` 与 `installed.json` 都沿用既有的"同目录临时文件 + rename"原子写。
不引入跨进程锁（会带来锁竞争与死锁风险），接受后写覆盖；设置窗口在提交前重新读取一次，
以缩小覆盖窗口。

### 5.3 FR-022 六字段的来源

| 字段 | 来源 |
| --- | --- |
| 名称、简介 | core 内置静态表（`id → (中文名, 简介)`） |
| 词条数 | `.zyct` 头部 `entry_count` |
| 体积 | 文件元数据 |
| 版本 | `installed.json`；未知则留空 |
| 启用开关 | `config.json` 的 `enabled_packs` |

名称与简介走内置静态表而非产物：manifest 生成时把 `name` 写成 `id`，中文名目前只是构建期的
打印常量，简介在产物与 manifest 中均不存在；同时 `.zyct` 头部只剩两段共 20 字节未写入的预留
区域，装不下中文名与简介，扩展头部等于改格式（D-37）。

### 5.4 导入本地 `.zyct`

用户选定文件后：读取并完整校验（魔数 `ZYDT`、格式版本、头部布局、内容 SHA-256）→ 复制到
`packs/<id>.zyct` → 写入 `installed.json`（`source: "import"`）。校验复用 `DictionaryFile::open`
（它本身即执行 `validate_layout` 与内容哈希）；导入是一次性操作，不走热路径，因此接受全文件
校验的开销。

**导入的包不验签**：它没有发布私钥签名，不参与在线更新的签名信任链。界面必须在导入处与列表
条目标注上说明这一点，避免用户误以为导入的包与在线更新下发的包具备同等来源保证。

## 6. 输入法管理与修复

### 6.1 注册状态判据

与 `scripts/ime-identity.ps1` 的 `Test-TsfRegistration` 保持一致：

1. `HKLM\SOFTWARE\Microsoft\CTF\TIP\{CLSID}\LanguageProfile\0x00000804\{ProfileGuid}` 存在且 `Enable == 1`
2. `HKLM\SOFTWARE\Classes\CLSID\{CLSID}\InProcServer32` 存在，默认值指向**实际存在**的文件，
   且 `ThreadingModel == 'Apartment'`

第 2 条的"目标文件需实际存在"是相对 `Test-TsfRegistration` 的**强化**（见 S-9），不是照搬。

标识常量（CLSID `{E54D6682-8650-40E7-A9EE-6FD1137849AE}`、ProfileGuid
`{6315FE74-92C3-439B-8CDF-FDB6E43EDAF1}`、语言 `0x00000804`、TFCAT
`{34745C63-B2F0-4784-8B67-5E12C8701A31}`）在 Rust 侧与 `ime-identity.ps1` 中双份存在。

**这份双份维护就是 D-42 的代价。** 约束是：两侧必须逐字一致，并由
`scripts/verify-tsf-identity.ps1`（T-079）从两侧提取常量做交叉比对，任一漂移即失败。
该脚本与既有的 `verify-tsf-dll.ps1` 同属"静态校验、不改注册表与文件系统"一类。

### 6.2 两级修复

**一级（无需提权）**

- 检测：注册状态判据；`packs/` 目录与各 `.zyct` 的魔数/格式版本/布局/内容 SHA-256；
  `config.json` 与 `user_words.json` 的可解析性
- 修复：重建缺失的 `packs` 目录；损坏的配置文件与用户词库**改名**为 `.bak` 后重建

**二级（提权）**

- 重注册两棵 HKLM 树：`SOFTWARE\Microsoft\CTF\TIP\{CLSID}` 与 `SOFTWARE\Classes\CLSID\{CLSID}`，
  先删后建，与安装脚本的幂等语义一致
- DLL 路径来源：先读当前 `InProcServer32`；读不到则取安装目录下最新的 `zhu-ye-ime*.dll`
  （安装使用版本化文件名，不能假定 `zhu-ye-ime.dll`）
- 完成后重启 ctfmon（D-43），使系统重新加载新注册

提权方式：主进程用 `ShellExecuteW` 的 `runas` 动词重新拉起自身的一个受限子命令
（`--repair-registry`），子命令只做注册表重注册并返回退出码，父进程据此展示结果。整窗不提权。

### 6.3 安全边界（D-41）

- **先报告后动手**：检测结果先展示，写盘与改注册表的动作必须由用户显式触发
- **只改名、绝不删除**：`user_words.json` 是用户的长期积累，一次误判不可逆；`.bak` 改名沿用
  `UserDictStore::load` 已有的备份语义
- **DLL 缺失只报告**："输入法文件缺失，请重新安装"——设置窗口无法凭空生成 DLL，不提供虚假修复

### 6.4 待实测确认的开放项

ctfmon 的重启方式（终止后由系统自动拉起，还是需要显式启动）需要真实 TSF 环境验证，
因此该项在 VM 恢复前属于开放实现项，实现时以 VM 实测口径为准并回填本节。

## 7. 检查更新

设置窗口的"检查更新"通过 `updater_bridge` spawn `zhu-ye-updater.exe` 并解析其输出，窗口自身
不发起网络请求（D-44）。`online_update` 默认关闭（P-03）：未勾选时界面禁用检查按钮并说明
原因，不发起任何进程与网络动作（保持"关闭时零出站连接"可测）。应用更新需二次确认。

P-02 的"启动时异步检查一次"不在本期实现（D-45）：它会把进程创建引入输入法的启动路径，
影响冷启动验收与宿主进程行为，且其验证必须依赖 VM 上的真实宿主；该能力立为独立任务，
P-02 在文档中标记为部分兑现。

## 8. 发行与安装改造

`install.ps1` 现在从源码树取 DLL（必要时现场构建）、只复制一个基础词典、不创建 `packs`
目录、不复制 manifest、不创建快捷方式，因此**无法作为"修复"后端**，也无法把设置窗口交付到
目标机。本期改造（D-46）：

1. 从发行包自身目录取文件，不再依赖源码树
2. 安装 `zhu-ye-settings.exe` 与 `zhu-ye-updater.exe`
3. 预置三个领域包到 `%APPDATA%\ai-zhu-ye-ime\packs\`（`it` 0.91 MB、`med` 1.31 MB、
   `slang` 0.03 MB，合计 2.25 MB，相对基础包 23.06 MB 占比约 9%）
4. 创建开始菜单快捷方式
5. `package-portable.ps1` 的包结构同步更新

预置领域包使 FR-042 可**离线**验收；在线更新保留，定位从"唯一获取途径"变为"版本升级途径"。

## 10. 风险与缓解（对抗性审查）

| 风险 | 缓解 |
| --- | --- |
| 注册责任从脚本扩散到设置窗口，两处实现漂移 | 交叉一致性门禁脚本（T-079）；标识常量只增不改；Agent Note 记录该不变量的部分取代 |
| `installed.json` 是新增磁盘格式，未来字段变更可能破坏降级 | 独立版本号；版本高于支持时按"未知元数据"降级而非失败；清单损坏时仍能列出实际存在的包 |
| 设置窗口与更新器并发写 `config.json` | 双方都走原子写；设置窗口提交前重读以缩小覆盖窗口；不引入跨进程锁 |
| 发行流程改造影响既有安装验收 | 安装脚本保持幂等与回滚语义；改造批次单独验收（干净机安装 + 卸载回滚） |
| VM 不可连导致全部交互验收欠账 | 双轨验收（D-47）：纯逻辑与渲染当场取证，交互项显式挂起、不谎报通过；第八期按"实现完成、验收欠账"结项 |
| 提权子命令成为新的攻击面 | 子命令只做注册表重注册、不接受任意路径参数、DLL 路径由自身安装目录推导 |
| 设置窗口跟随系统深浅色被误读为撤销 T-030 | 设计文档与 Agent Note 明确 T-030 只约束候选窗；两窗口的深浅色口径互相独立 |

## 13. 设计层决策（S-7 至 S-9）

沿用方案设计的 `S-xx` 系列（S-1 至 S-6 见 [方案设计.md](./方案设计.md)）。这三条是设计层
决定、非用户拍板的需求口径，故记在本文件而不进需求文档的 `D-xx` 决策表。

| 编号 | 决策点 | 决策与理由 |
| --- | --- | --- |
| S-7 | `config.json` 格式版本 | **不递增** `CONFIG_FORMAT_VERSION`。加载器对"版本高于当前支持"的处理是回退默认（仅基础包），递增会让一次降级安装丢掉用户已勾选的 `enabled_packs`；纯增量可选字段在反序列化时天然向后兼容，不需要版本门槛保护 |
| S-8 | 并发写口径 | **不引入跨进程锁**（会带来锁竞争与死锁风险）：`config.json` 与 `installed.json` 均沿用"同目录临时文件 + rename"原子写，接受后写覆盖；设置窗口提交前重新读取一次以缩小覆盖窗口。**两个写入方（设置窗口与更新器）都必须遵守该规则** |
| S-9 | 注册状态判据 | 以 `Test-TsfRegistration` 的三条为基础，**增加**"`InProcServer32` 默认值指向的文件必须实际存在"。原版只比对调用方传入的路径（`uninstall.ps1` 正靠传 dummy 路径来断言缺席），省略存在性检查会在 DLL 被删后仍报"已注册"。强化版用于状态展示；卸载断言仍用原版 |
